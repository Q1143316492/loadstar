# lodestar

自己的 AI 工作流技能库。上游三套库（`reference/`）是**取材对象**，不是复刻对象；产物长在 `workflow/`。

**入口**：

- [`docs/workflow-notes.md`](docs/workflow-notes.md) — 当前的设计与进度（四层模型 · 依赖顺序 · 存储分工 · 未定项 · 已否决项）
- [`docs/attempts/`](docs/attempts/) — 尝试记录，一次一条

## 尝试记录

同一个大需求试过几次、每次的结论。**失败的要留在最前面**——否则下一个会话（或 agent）会把死路再走一遍。

| # | 目标 | 结论 | 记录 |
|---|---|---|---|
| **01** | 产出「理解代码库」的文档 | **不成立** | [`attempts/01-codeview.md`](docs/attempts/01-codeview.md) |
| 02 | 改善代码库（失控库排查 / 重构 review） | 未开始 | — |
| 03 | 待定 | 未开始 | — |

> 每次尝试独立成文，放在 `docs/attempts/<NN>-<名字>.md`。README 只保留这张表和下面的通用结论；
> 「这次想做什么、做了什么、踩了什么坑、留下什么」全部写进各自的文件，不往上堆。

## 什么算「一个技能成立」（来自尝试 01）

三条**同时**满足才成立：

| 判据 | 含义 | 尝试 01 的反证 |
|---|---|---|
| **① 意图由人给定** | 需求 / issue / 不变量 / 规范 | 代码里读不出「什么重要」：EqZero 的 GAS 流程写到第 8 步就断在蓝图里 |
| **② 输出可被打脸** | 跑测试 / 复现 / 对照代码 | v4 的关卡只能查结构，内容写错了也无法判定 |
| **③ 范围有界** | 一个 diff / 一个模块 | 全库无法定义「做完了」与「漏了什么」 |

**② 尤其重要**：它是判断一个技能是否只是空操作的唯一方式。没有它，你分不清「技能起作用了」和「技能什么都没做」。

## 关键语句

从上游技能库里挑出来的五条。都是**看过实测或原文之后才取用**的，不是抄来的口号。

### 1. 空操作判据

> 模型默认就会照做的指令，等于白花上下文。测法：**把它删掉，行为会不会变？** 不会变就别写。

- **为什么**：每条指令都在花两样东西——**上下文**（每轮都占，无论是否触发）和一次**改变行为的说服**（希望）。如果模型不看这条也会那么做，那这条只花了前者。所以判据是**相对模型的默认**，不是相对读者的：两个人争论某句话该不该写，争的其实是「模型会不会默认照做」，而这个只能跑一遍来定，不能靠辩论。
- **出处**：`writing-for-agents`。原文还给了推论：一句没通过测试的话，**删掉整句**，而不是从里面裁掉几个词。
- **对本仓**：这是尝试 01 失败的直接解释。那个技能的核心动作是「分析代码库、产出文档」，而**这正是模型的默认动作**；改外壳（地图 / wiki / 索引 / 文档集 / 路线 / 契约）动不了默认，所以产出约等于直接聊。同一把尺子也解释了「要彻底（be thorough）」为什么没用——默认已经挺彻底，换成 `relentless` 才算超过默认。

### 2. 刻意偏离要记下来

> 刻意偏离显而易见路径的做法，必须写下来，否则下一个人会来「修正」某个本来就是刻意的东西。

- **为什么**：一个决定值得记录，要三个条件同时成立——**难逆转、不写就费解、是真实取舍的结果**。其中「不写就费解」最典型的一种，就是**一个合理的人看到现状会假设相反的做法，并且会动手把它改回去**。写下来，是为了挡住这次修正。
- **出处**：`ADR-FORMAT.md`。它列举的资格里包括「刻意的偏离」与「被否决、但否决理由不显然的方案」。
- **对本仓**：`workflow-notes.md` 里那份「已否决的」清单就是干这个的。它的必要性在本次对话里被实测过一次——**没读尝试 01 的记录，就提出了它已经否决的方案**（手工做导览文档）。那份清单就是挡这个的。

### 3. 建检查，而不是写规则

> 机械性违规配一个确定性检查；文字规范只留给真正的判断题。

- **为什么**：违规分两类。**机械的**（固定语法模式、被禁的 API、import 形状、文件位置规则）不涉及判断，可以直接写成检查——linter 规则、pre-commit hook、CI job；这些不依赖模型状态，每次都会执行。**判断题**（跨文件一致性、「和周围风格保持一致」）写成检查会误报，才留在文字规则里。原文的推论是「默认去建那个检查，而不是写那条规则」。
- **出处**：`retro`。
- **对本仓**：这是四层模型（信息 / 流程 / 纪律 / 强制）的来源。一句话：**能用检查兜住的东西，不要写成措辞**——检查跨模型稳定，措辞会随模型和版本漂移。

### 4. 先读，再断言

> 在说某个技能做什么、或建议跳过某一步之前，先读那个技能的 `SKILL.md`；摘要只用于定位方向。

- **为什么**：router 技能里的摘要是给人看方向的，压缩过。拿摘要去下判断，判断就建立在压缩损失上。这条的价值不在于「多读一遍」，而在于它指出**摘要和正文是两种东西、两种用途**。
- **出处**：`ask-matt`。
- **对本仓**：这条记录的是本次对话里**真实发生过的错误**（见第 2 条）。README 把尝试记录放在最前面、把失败标出来，用的是同一个道理。

### 5. YAGNI 划范围

> 没人改的代码里的重构机会，永远收不回成本；先用 `git log` 找热点。

- **为什么**：深化一个模块的收益是「**以后**改它更容易」。如果那个地方根本没人改，收益永远兑现不了——所以「扫全库、平均用力」在方法上就是错的，应该先看最近在改哪里，再决定看哪里。
- **出处**：`improve-codebase-architecture`。
- **对本仓**：它是「改善代码库」这条路的可行性来源。实测中它跑 EqZero 筛出了两个真问题（`GameFeatureAction` 重复记账、Experience 状态机的双重进入风险），可行性就来自**划范围 + 两次筛选 + 只出候选不改代码**。

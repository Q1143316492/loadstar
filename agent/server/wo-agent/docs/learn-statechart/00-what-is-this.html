01wo-agent 是什么

一句话：一个用纯 Python 写的 agent 内核，可以直接 import 进别的程序。

它是什么

一个 agent 循环的实现：把「模型 → 工具调用 → 结果 → 再问模型」这个循环写成一个可复用的 Python 包。

它不是什么

不是 Claude Code 的替代品，不做通用编码宿主，不做 skill 生态、不做 subagent、不做沙箱。`CLAUDE.md` 里有明确的定位判断。

给谁用

给 Python / C# 宿主（编辑器、桌宠、游戏引擎）一个能塞进去的 loop。运行时只依赖 httpx。

规模

9 个包、40 个测试文件、255 个测试。测试全用 fake provider，不联网、不要 key。

模块分层（单向依赖，禁止反向）

compose/按 Capability 组装一次运行——什么能力挂上去，在这里决定
agent/Agent 接口与 ReAct 循环。inbox 就在这里
session/事件溯源会话：append-only 日志，模型可见历史由日志派生
llm/LLM 接入：协议、类型、Provider 适配（DeepSeek 是唯一特例）
tools/ · workspace/ · skill/ · system_prompt/ · compaction/工具执行、工作区、技能、提示词组装、上下文压缩

核心设计：会话是一本 append-only 的事件日志，模型看到的历史是从这本日志派生出来的。日志是唯一事实源——所以审计、重放、分叉都免费。

今天学的 fold_surface 就是「派生」那一步的函数。

02Inbox 是干什么的

它是用户说话的入口。而它有个不太直观的设计：说话和「被模型看见」是两件事。

你跟 agent 说话时不希望它立刻打断当前的动作。所以 wo-agent 把消息先排队，等当前这一步跑完，再由循环去「认领」（claim）。认领之后才写进会话日志——模型这时候才看得见。

next-step下一步就用
「停一下，改成 X」 工具结果 → 当前这一步结束，立刻带上

代码里：steer() / inject() 推到这里

next-turn下一轮再用
「再帮我看个别的」 → 这一整轮跑完，下一轮开头才取

代码里：followup() / enqueue() 推到这里

已认领模型看见了
被 claim 取走之后，写成 user/message 事件进日志

claim 的实际规则（就这几行）

def claim(self, target):
    claimed = list(self._next_step)   # ① 总是先倒空 next-step
    self._next_step.clear()

    if target == "next-turn" and self._next_turn:
        claimed.append(self._next_turn.pop(0))   # ② 轮次开头再取一条

    return claimed

为什么要有两级？因为「打断当前步骤」和「排到下一轮」是两种完全不同的语义。混成一个队列，就无法表达「这条要立刻生效」。

C. 踩了一个坑

第一次跑 TLC 卡住不停。原因是 id 计数器无限增长，状态空间无穷。

加一行 CONSTRAINT NextIdBound == nextId <= 4 才好。这就是 TLA+ 最经典的翻车方式——也是「有界」这个词的由来。

这一步的意义：规格是独立于代码的一份描述。智能体改了 inbox.py，规格不会自动跟着变——所以不一致会被发现。这就是「怎么信任智能体」的机制部分。

下一步有个真问题需要你决定：
TLC 找到的反例是「claim 漏记了一批消息」。但真实代码的 claim 没有「已认领」这个变量——它直接返回列表。所以这个 bug 在代码里表现为「返回值少了一条」。

翻译成测试时要选：按模型的字面意思翻（可能翻不出来），还是按代码的表现翻（能翻出来，但和模型不完全对应）。后者更有用，但需要你在测试里显式写「返回值必须包含所有 step」。

把代码读成一张状态表

对象是 fold_surface。它只有一个状态变量 nodes，只有一件事会让它变：来了一条事件。下面把答案直接摆出来，你快速看形状。

01七行表

左列是事件给这个函数带来的全部可能，右列是它对表层的影响。

事件表层怎么变
投影为 None什么都不做。事件留在日志里，但不进表层。
append尾部追加一格。表层变长。
replace 合法把表层里 start 位置到 end 位置这一段整段换成一个节点。表层可能一下子短好几格。
replace 找不到节点报错 A：start / end 不在表层里。
replace 位置反了报错 B：start 的表层位置晚于 end。比较的是位置，不是数值。
source 漏了节点报错 C：被遮蔽的节点必须逐个列入 source。
source 指向未来报错 D：source 里有 ≥ 当前事件 seq 的值。

02全部的关键：日志和表层是两层

这是整篇唯一需要真正记住的东西。剩下的都是推论。

① 四次 append
日志 0123
表层 0123
② replace(1, 2) —— 这是一条新事件，占 seq 4
日志 01234
表层 043

1 和 2 被一个新节点 4 取代。被取代的节点没被删除，只是不再上表层（虚线）。注意表层长度从 4 变成 3。

而现在，顺序反了。表层是 [0, 4, 3]——seq 3 排在 seq 4 后面。数值大小不再是表的顺序。

所以在这一刻调 replace(3, 4)：数值上 3 < 4 看起来完全正常，但按位置算，3 在后面、4 在前面，报错 B。这就是为什么 start/end 必须是 seq（名字），不能是下标或数值区间。

「事实源是日志，表层只是投影」——被遮蔽的节点还在日志里，所以 derive_messages() 每次都是从日志重折一遍。审计、重放、分叉都因此免费。

03四种错，两类

A · B —— 调用方把位置说错了

找不到节点、或者位置反了。报错能直接告诉它错在哪，改参数就行。

C · D —— 数据自相矛盾

事件自己携带的溯源信息与日志的实际内容对不上。D 更严重：它声称的因果顺序是倒置的，日志不再可信。

这个区分在第 04 篇会变成两种建模选择：A/B 是「参数校验」，C/D 是「日志完整性不变量」。

04这跟「信任智能体」有什么关系

你真正的目标在这里，所以多说三句。

  1. 智能体说「改好了」是自述，不是证据。上面这张表是你可以自己跑、自己核的判据——它把「我认为对」变成「任何事件序列下都对」。
  2. 但规格也可能是智能体写的。所以规则是：必须见过它失败一次。第 03 篇就是干这个——把校验拿掉，看检查变红。没红过的检查等于没有。
  3. 所以验证要留在仓库里、能重跑、记着核对到哪个 commit。这正是 pstack 的 create-formal-verification-skill 在解决的问题：不是学会一个新工具，而是给智能体的工作装一个不依赖它自述的判据。

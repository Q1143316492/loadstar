learn-statechart / 你要学的到底是什么

你学的不是 TLA+，是一套五步流程

TLA+、TLC、Java 都只是这套流程里某一格的工具。流程本身才是能带走的东西——换语言、换工具、换项目，五步不变。

一句话

给一段代码划出「状态」，让机器穷举所有执行顺序，找出违反你规则的那条最短路径，再把它变回一条能重放的测试。

为什么值得学：智能体说「改好了」不算证据。这套流程给出一个不依赖它自述的证据。

01五步流程

下面每一步旁边都填了刚才 Inbox 的真实数据——你看到的不是范例，是实际跑出来的。

1

挑一条规则

人做

写出「任何时刻都该成立」的一句话。要满足三条：一句话能说完、能指到具体代码、真的可能被违反。

Inbox 实例
「每条推入的消息，要么还在队列里，要么被认领过——不会凭空消失。」
2

划出状态

人和 AI 一起

决定哪些变量算状态、哪些细节扔掉。这一步最贵，也最没有工具能替你做。

Inbox 实例 · 5 个变量
nextTurn 队列 · nextStep 队列 · claimed 已认领 · pushed 推送过（代码里没有，为写规则加的）· nextId 计数
扔掉：消息内容、协程、cancel 的用法
3

机器穷举所有顺序

机器做

不是随机撞，是把每一个能走到的状态都走一遍。同一个状态只走一次。

Inbox 实例 · 实际输出
Model checking completed. No error has been found.
63 distinct states found, 0 left on queue.
The depth of the complete state graph search is 7.
4

故意改坏，必须能失败

人做

这步不能省。一个从没红过的检查，和一个不存在的检查，价值相同。

Inbox 实例 · 删掉一行「记下已认领」
Error: Invariant NoLoss is violated.
State 2: PushTurn    nextTurn=<<0>>   pushed={0}
State 3: PushStep    nextStep=<<1>>   pushed={0,1}
State 4: ClaimTurn   nextStep=<<>>    claimed={0}   ← 1 不见了
5

把反例变回测试

你在这里

机器给的是「三步路径」。把它翻译成真代码里的一条测试，跑绿。这样智能体以后改坏了，测试自己会红——不需要你信它说什么。

要做的事
把 PushTurn(0) → PushStep(1) → ClaimTurn 翻成对 Inbox 的调用，断言「返回值里必须有 step 那条」。

02每一步在买什么

如果哪一步不买你想要的，那一步就可以砍掉。

第 1 步买到

把「我觉得应该对」变成一句可检验的话。没有这步，后面机器再强也只在验空气。

第 2 步买到

一个足够小、又足够真的模型。太大跑不完，太小验不出东西。这是人的判断力所在。

第 3 步买到

「测完了」这句话。随机测试说不了这句，TDD 更说不了。穷举能。

第 4 步买到

对检查本身的信任。见过它红，才知道它绿意味着什么。

第 5 步买到

一个会自己报警的哨兵。这是唯一一步的产出能留在仓库里、天天替你干活。

只在第 3 步用到 TLA+ 和 Java。如果你用 Python 自己写穷举（教程里的 exhaustive_fold.py 就是），第 3 步可以完全不用 TLA+。

TLA+ 换来的额外东西只有两个：不用自己写调度器、能验证「终将发生」这类活性性质。

03「学会了」的判据

不是读完，是能独立走完这五步。

你已经做到了前四步（用 Inbox 走完一遍，每一步都有实际输出）。

剩下的只有第 5 步——把反例翻成测试。翻完，第一轮就算学会了。然后换第二个对象再做一遍，才算真的会。

诚实提醒：这一遍是我带你走的。第 2 步「划出状态」是我替你做的——那才是这套东西最难的部分。真正的学习发生在你自己划一个对象的时候，那时你会不确定「这个变量要不要算进状态」。

下一步：第 5 步。把 TLC 给的三步反例翻成一条 pytest 测试，跑绿，然后故意改坏 inbox.py 看它红。

做完之后，你就有了一个可以天天跑、不依赖任何模型自述的哨兵——这就是「怎么信任智能体」的最小可运行答案。

learn-statechart / 概念地图

为什么 TDD 抓不到，这个测试到底叫什么

三个问题，三个答案。中间用同一段代码并排对比，你看得见差别在哪。

00先给答案

TDD 为什么不能解决

不是「测得不够多」，是测试从空状态出发、每次只走一条路。而 bug 住在两条合法路径的组合里——没有人会想到写那个组合。

这个测试叫什么

叫有界穷举的、基于状态机的属性测试（exhaustive stateful property-based testing）。它借用了模型检查器的机制，但还不算严格意义的「形式化验证」——因为它有界、而且不验证规格。下一节有阶梯图。

它具体做了什么

三步：枚举所有合法操作 → 广度优先走遍状态、同一个状态只走一次 → 每到一个状态就检查规则。失败时给你一条最短的、能重放的操作序列。

02具体逻辑：它凭什么能自己找到问题

拆开 test_fold_surface.py 看。

1

枚举「合法」的下一步

一条历史之后，下一步可以是什么？两种：追加一条新消息，或者替换当前表层里的某一段。

关键在这里：不是随机挑，是把所有合法选项都列出来。successors() 负责这件事。

2

广度优先走遍，同一个状态只走一次

每走一步，就得到一个「历史 + 当前表层」的组合。这个组合就是状态。

如果两个不同的历史折叠出同一个表层，后面的路完全一样——只走一遍。这就是去重，也是它能扛住指数增长的原因（实测：深度 8 省掉 93%）。

3

每到一个状态，检查规则

规则是「任何时刻都该成立」的断言，比如：表层不能有重复节点；替换掉的节点不该还留着。

违反了？立刻停。因为广度优先，你拿到的这条路径天然是最短的。

实际跑出来的失败长这样：

序列 ('append', (0,0), (1,1)) 违反：replace(1,1) 之后仍残留 [1, 1]

三步、一条完整路径。你照着这三步在真代码里复现，一定能重放。

03它到底叫什么——阶梯

这些词经常被混用。从下往上，严格程度递增。我们站在倒数第二级。

单元测试unit test
你给输入、断言输出。覆盖你想到的用例。
属性测试property-based testing
你写「无论什么输入都该成立」的规则，机器随机生成输入去撞。代表：QuickCheck、hypothesis。不知道漏了什么。
状态化属性测试 · 有界穷举stateful property testing / exhaustive
就是我们的测试。规则相同，但输入不是随机的——是按状态空间枚举的。所以能说「这个深度内我测完了」。名字里的两个词：stateful（有状态、论顺序）、exhaustive（穷举，不是抽样）。
模型检查model checking
同样的穷举机制，但用在一份独立的规格上，而不是你的代码上。代表：TLC、SPIN、Apalache。会检查时序性质（「终将发生」），我们的测试不会。
形式化验证formal verification
模型检查、定理证明（Coq、TLAPS）的统称。特征是对某个明确界定的范围穷尽地证明，不靠抽样。

诚实地说：我们的测试是「半只脚踏进形式化验证」。

它和模型检查用的是同一个引擎（穷举 + 去重 + 最短反例），但它有两个缺口：一是有界——深度 5 以外没测；二是直接在真代码上跑，没有一份独立规格可以拿来对照。

所以你之前听到的「TLA+」，正是补这两个缺口的东西。而如果这两个缺口对你的场景无所谓——那这个 100 行的 Python 测试就够了。

04为什么人想不到那个组合

用 wo-agent 真实的压缩场景。

会话压了一次、又压一次，表层顺序和日志顺序就错位了：

起始     表层 [0, 1, 2, 3]      四轮对话
压缩1    表层 [4, 2, 3]         前两条换成摘要(seq 4)
压缩2    表层 [5, 3]            又换成摘要(seq 5)

日志 seq:  0 1 2 3 4 5   ← 永远递增
模型看到:      5 3       ← seq 大的在前

写单元测试时，你想的是「压缩一次应该怎样」。压缩两次之后表层是什么形状，取决于前一次挑了哪一段——这个组合是人写不完的。

序列长度可能的组合数人能写完吗
3~33勉强
5~138不能
7~3,894不能
8~24,471不能（但机器 0.3 秒）

失败长什么样：模型读到的对话顺序是乱的，然后开始胡说。日志完全正常——所以你查不到。

这不是「测得不努力」，是人脑不适合枚举组合，而机器适合。

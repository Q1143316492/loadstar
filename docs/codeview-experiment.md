# 让 AI 生成"理解代码库"的文档：做了什么、为什么失败、结论是什么

**pi-mono**（TS monorepo，1,927 文件，14 个包）。两份源码仅用于测试，不入归档。
> 本仓背景记录：对应 [`README.md`](../README.md) 的「需求，与已经踩到的坑」一节，结论已摘进 [`docs/workflow-notes.md`](workflow-notes.md)。

## 读前须知
+ **本文回答什么**：我们为什么想做「让 AI 帮你理解代码库」的技能、做了什么、**为什么最后判定它不成立**、以及留下什么可用件。
+ **本文不回答什么**：不教怎么写技能、不教怎么用 AI 读代码（那正是本文判定不成立的方向）；也不含环境/工具层面的操作细节。
+ **怎么读**：只想看结论 → §3；想看证据 → §1（做了什么）与 §2（四层失败原因，每层有实例）。

**术语表**（只列**读者可能不认识的外来词、缩写与本文自造词**；本行的词——如"虚幻/GAS/蓝图"——不列）

| 词 | 在本文里的意思 |
| --- | --- |
| **判据（oracle）** | 能**自动**判定输出对错的标准，例如单元测试跑不跑得过、变异杀伤率、召回率。本文的核心论点就是：理解型文档**没有判据** |
| **变异杀伤率** | 往代码里故意注入小改动（变异）再跑测试：测试变红=这个变异被杀掉；被杀的比例就是测试质量的分数 |
| **召回 / 噪声比** | 代码评审里：召回 = 真实缺陷中被找出的比例；噪声比 = 提出的意见里没用的比例 |
| **锚点** | 指向代码位置的写法：`相对路径#符号名`（不用行号） |
| **YAGNI** | "You Aren't Gonna Need It"：只做现在需要的，不为设想中的未来先写代码 |

## 0. 目标
做一个**可复用的 agent 技能**：让 AI 分析一个陌生的代码库，产出**帮人理解它**的产物；机械活交给脚本，判断留给模型。  
产物落在 `<repo>/.codeview/`，可进版本库。**目标从来不是"生成这个项目的文档"，而是沉淀一个流程。**

## 1. 我们做了什么

### 1.2 工程量（v1 的工具链是最重的一块）
`scan.py`（25KB：目录/计数/引用索引/领域词/git 热区）、`directories.py`（17KB：四道关卡）、`verify.py`（18KB：`.map` 解析 + 锚点校验）、

**133 个测试**（含页面冒烟、原子写双红证）；启动器 `CodeView.bat`；技能目录共 **62 个文件**。

### 1.3 实测数据（全是跑出来的，不是估的）
+ 全库覆盖式分析：EqZero **623 文件 / 72,645 行** → 约 **10 分钟**、216 节点。
+ **范围先行**：按 git 热点/可达性压缩 → **108 秒**（61 个文件压到 8 个源码文件，只读接口 + grep 调用点）。
+ 机械解析：**0.6 秒**处理 520 个 C++ 文件（对比模型侧的分钟级）。
+ 成本度量（从 harness 会话日志 `~/.dsh/storages/session_projcache/sessions/<agent-id>.json` 的 `tokenUsage` 读）：  
v2 = 94,405 output tokens / 6:43；v3 = 44,970 / 4:50。**平均 ≈234 output tok/s——模型不慢，是任务输出量大。**
+ 关卡在**真产物**上三次报红：多余文件没进索引 / 第二张表的表头被当成"未表态的索引行" / **检查器自己把索引路径截成 basename 导致"文件不存在"**（玩具样例测不出这三个）。

### 1.4 对照实验（用第三方技能当标尺）
把 `improve-codebase-architecture`（mattpocock，MIT）拉到本地跑同一批仓库：

+ 跑**本仓库**：**108 秒**，5 个候选 + 1 条 Top recommendation，**未改一行代码**。最强候选：六道 `.map` 关卡里存在两条互相矛盾的"谁算子目录"规则（`indent >` 与 `indent == +2`）。
+ 跑 **EqZero**：6 个候选。头两条：① `GameFeatureAction` 家族重复实现可逆授权记账（`AddInputContextMapping.cpp` 注释自陈 "ControllersAddedTo is never modified"；`EqZeroHeroComponent.cpp` 里 `RemoveAdditionalInputConfig` 是 `//@TODO: Implement me!`）；② Experience 加载状态机有"双重进入"风险（`OnGameFeaturePluginLoadComplete` 不检查 LoadState，`OnExperienceFullLoadCompleted` 里有 `check`）。
+ 它的可行性来源很具体：**YAGNI 划范围 + 两次筛选 + 每个候选配 before/after + 结论只指向文件**。
+ 我们把该技能全文译成中文并加注 21 条（值得吸收 16 / 与我们不同 3 / 可疑代价 2），另外把 `codebase-design` 的深度词汇（小接口大行为、接缝、适配器等）也过了一遍。

## 2. 为什么失败（四层原因，每层都有实证）
### 2.1 "什么重要"不在代码里——它在意图里
| 实例 | 具体事实 |
| --- | --- |
| EqZero 的 GAS 流程**写到第 8 步就断了** | 第 1–7 步都能读到锚点（输入 tag → ASC 调度 → 目标数据 → 服务器确认）；第 8 步"伤害 GE 在蓝图里施加"——`DamageEffectClassCppUse` 属性**没有任何调用点**。**代码里能读到的链到此结束**，文档只能写"此处是洞" |
| pi-mono：**14 个包，README 只写了 7 个** | 另 7 个（`client`/`codemode`/`env`/`evals`/`mcp`/`protocol`/`server`）在 README 里一个字都没有；读目录名与文档**无法判断它们是内部库还是废弃代码** |
| 作者一眼指出 v3 产物**漏了 UI、生命值、系统数值、动画** | 这些正是"该讲哪些"的定义。**作者的"重要"清单不来自代码**，AI 猜必然漏 |


### 2.2 没有判据 ⇒ 迭代只能优化「外观」
v4 把结构做到了极致：七节骨架、索引双向一致、锚点逐条核对、六条检查、红证齐全，`check.py` 353 行、真实产物 `OK`。  
**但用户的判定是"我还是不知道从哪里下手"。** 关卡能查"锚点存不存在、索引一致不一致、行数超没超"，查不了"内容对不对、值不值得看"。  
于是每一轮改进都落在**形式**上（图 → wiki → 索引 → 文档 → 路线 → 契约），而用户的判据是"这对我有没有用"——**两者永远对不上**。

### 2.3 范围无界 ⇒ 无法定义"做完了"和"漏了什么"
全库版（623 文件 / 10 分钟 / 216 节点）被判"很零散"；v4 的 229 行目录注解覆盖 310 个目录，被判"全扫没必要"。  
反过来，**有界的那次（61→8 个文件 / 108 秒）挖到了真问题**。同一个模型、同一批代码，差别只在范围。

### 2.4 产物定位错了：它是"输入"，不是"给人读的文档"
唯一被验证有用的用法：**把 v2 的 10 步阅读顺序当"范围输入"喂给下一步工作**——只读了 8 个源码文件，就定位到两个真问题  
（Experience 加载状态机的双重进入风险；输入映射里那句 `//@TODO: Implement me!`）。  
而"给人读"这个用法，用户的评价始终是"**不如我自己一个文件一个文件去问 AI**"。

## 3. 结论
### 3.1 判据（三条同时满足，这类技能才成立）
| 条件 | 我们踩的反证 |
| --- | --- |
| **① 意图由人给定**（需求 / issue / 不变量 / 规范） | 2.1 的三个实例：不知道什么重要，必然漏 |
| **② 输出可被打脸**（跑测试 / 复现 / 对照代码） | v2 的 6 个模块页写错了也无法判定；v4 关卡只能查结构 |
| **③ 范围有界**（一个 diff / 一个模块） | 2.3：全库无法定义完成与遗漏 |


### 3.2 成立 / 不成立
| 场景 | ① | ② | ③ | 结论 |
| --- | --- | --- | --- | --- |
| 理解陌生代码库 | ✗ | ✗ | ✗ | **不成立**（本次实验的结论） |
| 十几万行全库找问题 | ✗ | 部分 | ✗ | **不该做成技能**（"全面"没有定义） |
| 一个 diff 的 code review（意图来自 issue） | ✓ | ✓ | ✓ | **成立** |
| 明确不变量下的测试生成（用变异杀伤率评分） | ✓ | ✓✓ | ✓ | **成立** |
| 模块拆分不好时"补测试" | ✗ | 部分 | ✓ | 会退化成表面测试 |


### 3.3 这次留下的可用件（具体格式与实测，不是原则）
1. **锚点格式 **`相对路径#符号名`（不用行号、不含空格）：行号一改就烂，符号名只要不改名就成立。
2. **机械关卡 + 红证**（`check.py` 353 行、六条）：① 六节齐（缺哪节点名）② 索引双向一致（索引里的文件必须存在；磁盘上的功能页必须进索引）③ 锚点真实（`路径#符号` 能在代码里找到该符号）④ 必备文件（`OVERVIEW.md` 必须在）⑤ 行数上限（功能页 ≤120 行）⑥ "已展开"必须有实质内容（只有骨架的页面不许标完成）。红证方式：改坏 → 必须报红 → 改回 → 必须变绿。
3. **逐项表态**：允许漏，但漏必须写成 `未展开（原因）`——pi-mono"7/14 个包没进 README"就是这么露出来的。
4. **登记规则**：只有"是什么"和"流程"有实质内容才允许标"已展开"；**搜过关键字不算内容**。
5. **一次只读用户点名的块**：没点名的一行不读。
6. **成本度量法**：`~/.dsh/.../sessions/<agent-id>.json` → `tokenUsage`（判断"快不快、值不值"用它，不用墙钟）。
7. **可吸收的现成形态**：`code-review`（两轴——Standards = 是否符合仓库标准，Spec = 是否符合发起它的 issue；三条判据全满足，可直接用）、`improve-codebase-architecture`（YAGNI 划范围 + 两次筛选 + 只出候选不改代码）、`codebase-design`（深度/接缝那套词汇，用来判断一个模块该不该改）。

### 3.4 不要再做 / 要再做的前提
**不要再做**：全仓库"理解型文档"（v1–v4 全部形态）、符号索引与扇入排序、手写节点树、把结论换个说法的"路线"。  
**要再做，只能**：给 **issue/需求 + diff** 做 review（评分：召回 + 噪声比）；给**明确的不变量**生成测试（评分：**变异杀伤率**）。  
两者都满足三条判据，而且**评分是数字，不是评价**。

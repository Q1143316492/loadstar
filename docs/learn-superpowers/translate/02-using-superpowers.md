## 2 using-superpowers

任何时候都要调用，除非是子agent。

<EXTREMELY-IMPORTANT>
如果你认为某项技能哪怕只有 1% 的可能性适用于你正在执行的工作，就必须调用该技能。
如果有技能适用于你的任务，你没有选择余地，必须使用它。
这一点没有商量的余地，你不能找理由规避该要求。
</EXTREMELY-IMPORTANT>

非常强烈的语气强调，必须调用这个技能在任何时候没有任何商量的余地。

### 2.1 规则

**在做出任何响应或执行任何操作之前**，调用相关的或被要求的技能——包括提出澄清问题、研读代码库或查看文件。如果发现它不适用于当前场景，则不必使用。

**进入规划模式前：** 如果你还没有进行头脑风暴，请先调用头脑风暴技能。

然后声明 “Using [skill] to [purpose]”（用某技能做某事），并严格按照该技能执行。如果它带检查清单，就为每一项建一个待办。

### 2.2 技能优先级（Skill Priority）

多个技能同时适用时，进程类技能优先——它们先定方法，再由实现类技能（如 frontend-design）去落地。头脑风暴和系统化调试是 Superpowers 最常用的两个进程类技能，但这条规则适用于任何进程类技能。

- “我们来做个 X” → 先调用 superpowers:brainstorming，再调用实现类技能。
- “修一下这个 bug” → 先调用 superpowers:systematic-debugging，再调用领域技能。

### 2.3 危险信号（Red Flags）

出现下面这些念头，就说明该停手了——你在自我合理化：

| 念头 | 真相 |
|---|---|
| “这只是个简单问题” | 问题也是任务。先检查技能。 |
| “我得先了解点背景” | 技能检查在提问澄清**之前**。 |
| “让我先翻一下代码库” | 技能会告诉你**怎么**翻。先检查。 |
| “我可以快速看下 git / 文件” | 文件不含对话上下文。先检查技能。 |
| “让我先收集信息” | 技能会告诉你**怎么**收集信息。 |
| “这不需要走正式技能” | 存在这个技能，就用它。 |
| “我记得这个技能” | 技能会演进。读当前版本。 |
| “这不算一个任务” | 动作 = 任务。先检查技能。 |
| “用这个技能太重了” | 简单的事会变复杂。用它。 |
| “我先把这一件事做了” | 做任何事**之前**先检查。 |
| “这感觉挺有产出” | 没章法的行动浪费时间。技能能防住。 |
| “我知道那是什么意思” | 懂概念 ≠ 用了技能。调用它。 |

### 2.5 用户指令（User Instructions）

用户指令（CLAUDE.md、AGENTS.md、GEMINI.md 等，以及直接提出的要求）优先于技能，技能又优先于默认行为。只有当你的“人类搭档”（your human partner）明确让你跳过时，才跳过技能工作流或它的指令。

### 2.6 读后思考

下面只是这份文件暴露出来的机制，还在看「它有什么」，没到取舍阶段。

- **强制的是「先查」，不是「必用」。** README 说强制，这里说「不适用可以不用」——强制力全压在出手前先查这个动作上。
- **有出口的强制才守得住。** 绝对化措辞配一个逃生舱，缺哪一半都会失效。
- **Red Flags 表不是给人看的。** 它把模型自己的推诿台词提前贴成「自我合理化」，是预置的对抗样本。
- **常驻是有成本的。** 只有这份文件被注入到会话开头，3KB / 65 行，其余技能按需拉取。
- **压缩会冲掉常驻内容。** 所以要再注入一次；没有 post-compaction hook 的平台会丢 bootstrap，技能就不触发了。
- **description 写的是「何时用」。** 触发条件是 frontmatter 里那行，不是技能名。
- **优先级是分类，不是顺序。** 进程类技能定方法，实现类技能做落地，两者不构成流水线。
- **每条规则都带「谁不该读」。** 子智能体被排除：它没有对话上下文，再让它路由只会烧上下文。
- **权威层级：用户 > 技能 > 默认。** 技能不是最高法，用户显式说跳就能跳。
- **「your human partner」是刻意选词。** 上游明说不能换成 "the user"；称呼会塑造行为。
- **留白：「1% 可能就必须调用」没有判据。** 等于永远调用，实际靠逃生舱和模型自觉兜着；他们用 skill-behavior eval 反复压测来补这个洞。

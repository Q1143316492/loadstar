# 工作流设计笔记

> 2026-10-13 · **初步想法，未定稿**。整篇都可以被推翻。
> 这是一份一次性的上下文恢复笔记，不是权威文档；预计在一两次变更后失去价值。真正的产物在 `workflow/`。

## 1. 要去哪

一套自己的 AI 工作流。原定的四件事（**理解新代码库 · 重构 · code review · 测试**）里，**第一件已判否**——
不做一个「产出理解型文档」的技能（见 §5）。剩下三件共享同一个前提：**意图由人给定 + 范围有界**，
也就是给一个 issue / diff / 不变量，而不是「理解整个库」。

**核心原则：不教 AI 干活。**

不用 superpowers 那套措辞纪律（禁令 + 反驳表 + 红旗清单 + 措辞微测）。它把不变量寄托在说服力上，换模型或换版本就可能失效，而且维护精力全花在调措辞上——要的是让流程**绕不过去**，不是让措辞**更有说服力**。

## 2. 为什么要做（问题诊断）

上一轮尝试的三个症状，和各自的机制：

| 症状 | 机制 |
|---|---|
| 文档**笼统** | AI 读不完大库 → 自动总结 → 输出"平均化的描述"。「详细一点」救不了它 |
| **容易遗漏** | 文档里全是**不可验证的部分列举**，读者无从知道有没有漏 |
| **流程过重** | OpenSpec 三件套太重，轻量任务用不上 |

> 前两条不是猜的，是一次跑完五代的实测结论：[`01-codeview.md`](attempts/01-codeview.md)。
> 该实验还给出了更根本的判据——**一个技能要成立须同时满足「① 意图由人给定 ② 输出可被打脸 ③ 范围有界」**，
> 理解型文档三条全不满足，故不成立。**② 是判断一个技能是否只是空操作的唯一方式**：
> 没有它，你分不清「技能起作用了」和「技能什么都没做」
> （空操作判据的完整推理见 [`01-codeview.md` §4.1](attempts/01-codeview.md)，出处是 `writing-for-agents`）。

**笼统的可执行判据**（替代「详细一点」）：

> 拿这个库里一个真实 issue，只用这份文档，能不能定位到该改哪个文件？
> 能 → 够具体；不能 → 它笼统，无论写得多长。

**遗漏的解药是让覆盖可见，不是写得更全。**
「入口只有 3 个：a / b / c（验证方式：…）」远比「核心模块包括 A、B、C」有用——读者立刻知道自己看全了没有。

**学习文档的正确形状**：地图 / 索引 / 路径三者中，AI 只产出第一种且低分辨率，真正缺的是后两种。**路径（一次端到端的具体追踪，每行带 `file:line`）是学习的基本单位。** 笼统的技术定义就是：句子里没有可跳转的锚点。

> ⚠️ **以上三段已作废，留作教训**：它们是"这份文档该怎么设计"的推测，而实验结论是这个方向整个不成立。
> 尤其"路径是学习的基本单位"——那本质上是 v3「路线版」的换皮，而路线版被明确列为**不要再做**。
> 留着是因为它演示了一个真实的坑：**推理得再顺的形式改进，也换不来一个判据。**

## 3. 当前思考

### 3.1 四层模型（最核心的一条）

技能内容按「填哪种缺口」分四层，越往下越稳定、越不费措辞：

```
4  环境层   钩子 / CI / lint / 测试命令      一次性投入，跨模型 100% 稳定
3  纪律层   "压力下别偷懒"                   极高措辞成本，跨模型最不稳定   ← superpowers 在这
2  流程层   谁先谁后 / 产物长什么样           中等成本，跨模型稳定           ← matt 大部分在这
1  信息层   本仓的事实：地图 / 词汇 / 缝隙      最低成本，跨模型 100% 稳定
```

- **规则**：写任何祈使句之前，问三次能不能下沉；三问都沉不下去的才留在第 3 层。
  （「必须每次跑测试」→ CI job；「用我们的命名习惯」→ 规范文件）
- **关键**：第 2 层约束**产物**，不约束**手法**。约束放进步骤顺序里，不放进形容词里。
  例：matt 的 tdd 写「未确认的接缝上不写任何测试」（门槛是一个产物：缝隙清单），
  而不是「你必须先写测试」。
- 第 3 层不能为零，但它应该是**残余**，不是地基。碰上了优先引进别人压测过的。
- **来源**：「建检查 > 写规则」这条，原理与实例见 [`01-codeview.md` §4.3](attempts/01-codeview.md)——那次实验里六道机械关卡是唯一稳定发挥作用的部分，同时它的边界也暴露得很清楚（只能查结构，查不了内容）。

### 3.2 依赖顺序（已修正）

原先以为四件事并列，且「理解代码库」是其余三件的地基。**地基那条已被推翻**——那个方向不成立（§1、§5）。

仍然成立的是：**剩下三件（重构 / 测试 / review）共享同一个前提**，而它们需要的产物确实在它们之前：

```
  前提：意图由人给定 + 范围有界（一个 issue / diff / 不变量）

        ┌───────────────┬───────────────┐
        v               v               v
      重构            测试           review
        │               │               │
        └───────┬───────┴───────┬───────┘
                v               v
          需要：缝隙清单      需要：本仓规范
```

三个改造类技能本身几乎不用自定义，它们需要的只是**读这些产物**——比如 review 的 Standards 轴，在写出本仓规范之前是空的。**注意产物不再是"全库的导览"，而是随每个任务现取的局部事实。**

### 3.3 存储分工

| 存什么 | 存哪 | 谁写 |
|---|---|---|
| 系统做什么（what） | OpenSpec `specs/` | archive 流量 |
| 领域词汇 | `GLOSSARY.md` | grilling / domain-modeling |

**一条纪律**（抄 `improve-codebase-architecture`）：巡检报告写临时目录、**不进仓**——它是一次性的。
（原表还有一行「代码在哪 / 学习技能」，随 §5 的判否一并作废。）

### 3.4 计划层的三档路由器

| 档 | 存哪 | 判据 |
|---|---|---|
| 0 | 不入文件 | 想清楚就是产物 |
| 1 | IDE plan mode | 一个会话能做完；会话结束即蒸发 |
| 2 | OpenSpec change | **状态必须活过会话**：跨会话 / 要评审 / 改持久规格 |

**升级信号**（四条任意一条成立就升级）：① 会话快满（smart zone ≈ 150k）② 需要第二个人看 ③ 会改持久规格 ④ **今天做不完**（最实用的一条）。

三者是正交的，不存在「混用」问题：plan mode 是**交互界面**（在哪想），OpenSpec 是**存储 + 状态机**（存哪），技能是**程序**（怎么想）。

### 3.5 真正要写的比想象中少

原以为要从零写三样（① 理解代码库技能 ② 路由器 ③ 信息层文件）。**现修正**：
① 已判否（§5）；② 路由器要等有多个技能之后才有内容可画；③ 信息层文件只在真跑之后才知道缺什么。
**所以现在一样都不用写**——先在真实库上跑现有技能，让摩擦点告诉我们缺什么。

## 4. 还没定的（下次从这里继续）

**方向已改**：不再从"理解代码库技能"起步（那是死路，见 §5）。

**第一步**：拿一个**真实的失控库**跑 `improve-codebase-architecture`，找它的摩擦点。
它已在 EqZero 上验证能筛出真问题（`attempts/01-codeview.md` §1.4），可行性来自 **YAGNI 划范围 + 两次筛选 + 只出候选不改代码**。

  比 code review 更硬，且判据 ①②③ 全满足（见 `attempts/01-codeview.md` §3.2）。**还没试过**

## 5. 已否决的（省得重复讨论）

- **不做「理解型文档」技能**（尝试 01）—— 这是最初的需求，但已实测判否：五代产物、133 个测试、353 行机械关卡全做完后，
  判定**不成立**。三条判据（意图由人给定 / 输出可被打脸 / 范围有界）它全不满足。完整实验与可用件见
  [`01-codeview.md`](attempts/01-codeview.md)。**下次要提这个方向前，先读那份记录。**
- **不用 ADR** —— `ADR-FORMAT.md` 要求「难逆转」才写，而这里的决策明确预期会被推翻；且读 `docs/adr/` 的那 5 个技能是**别人的仓库在代码库上跑的**，本仓库没有代码，写了不会被读。互操作性的理由不成立。
- **不用 superpowers 的措辞纪律** —— 见 1 与 3.1。
- **不把这次的讨论记成 OpenSpec change** —— 设计还在迷雾里，围着移动靶画靶纸。等第 1 轮试跑后再说。
- **不记对话原文** —— 过程会变成 `sediment`（只增不减的沉积层）。思考压缩后的形式就是结论 + 开放问题；对话本身在会话日志里，`retro` 能检索到。

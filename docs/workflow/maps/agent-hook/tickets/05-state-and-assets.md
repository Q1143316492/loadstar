# 桌宠状态机与素材切换契约

## 问题

把「事件 → 状态 → 画面」这条链定死，好让效果后期能被单独替换。

要定：

- 状态全集：至少 `空闲 / 工作中 / 预警`；「静音」是独立状态还是**预警状态上的一个标记**（它只影响是否亮起，不改变会话在开会话的事实）。
- 每个状态由哪些事件进入 / 离开（对照协议票的事件类型，不重写协议）。
- 多会话时主形象的选优规则如何与状态机组合：是每个会话一个状态机、一个聚合器选最优，还是单一全局状态机。
- 素材契约：文件命名（如 `assets/idle.png`、`assets/alert.png`）、尺寸约定、「未知状态」的兜底图；换图只改文件不改代码。
- 气泡文案：由桌宠生成还是由事件携带；预警气泡的固定文案是什么样。
- 日志与状态的关系：状态迁移是否也写进日志，供事后核对「那次为什么没亮 / 为什么亮了」。

产出：一张状态迁移表 + 素材命名约定。

类型：grilling
状态：已解决
阻塞于：03

## 答案

### 状态全集

每会话三态：`空闲`（会话在、久无事件）、`工作中`（有事件流动）、`预警`（越过 02 票阈值）。**静音是预警上的一个标记，不是独立状态**——只决定不亮，不改变事实。

### 状态迁移表

| 从 → 到 | 触发 |
|---|---|
| 空闲 → 工作中 | `SessionStart`，或任意 `PostToolUse` |
| 工作中 → 预警 | 越过 02 票阈值 |
| 预警 → 工作中 | 该会话出现写操作 / `UserPromptSubmit` |
| 任意 → 空闲 | 该会话 30 分钟无事件（仅用于展示；`SessionEnd` 才是销毁） |
| 任意 → 销毁 | `SessionEnd` |

静音标记：点宠物时置位，写操作或 `SessionEnd` 时清除。

### 多会话聚合

每会话一个状态机，一个聚合器读全部：按 `预警 > 工作中 > 空闲` 选主形象，旁附 `N sessions · M alert`。多个会话同时预警时按「最早进入预警的优先」，主形象不在它们之间来回跳。

### 素材契约

- 路径：`agent-hook/pet/assets/<状态>.png`，即 `idle.png` / `working.png` / `alert.png`，兜底 `unknown.png`。
- 约定：256×256、透明背景。
- 换素材 = 同名覆盖文件；桌宠**启动时**加载，重启生效。热加载留到做动画时再考虑。
- 缺图用 `unknown.png` 并在日志里记一条。

### 气泡文案

桌宠生成，固定模板：`工作中` 显示 `Read · 12/25`（当前工具 + 计数）；`预警` 显示 `连续 25 次读未写`；`空闲` 不显示。多会话时只讲主会话。

### 日志

状态迁移写进 03 票定义的每会话 JSONL（`kind: "transition"`），与原始事件同流。

## 后补：取消静音（2026-11-20）

静音是原型期自加的交互，用户反馈从不需要（桌宠本来也不发声）。已整条移除：每会话的 `muted` 标记、`aggregate` 里因静音隐藏主形象的分支、状态机里的 `mute()`、`POST /mute` 端点、IPC 通道、气泡上的 🔇 按钮与菜单项。预警的解除条件（写操作 / 用户发言 / 会话结束）不受影响。

**声音**：当前不发任何声音。以后若要加，作为菜单项放进右键菜单，不做成常驻控件。

## 后补：多会话的气泡文案（2026-11-20）

聚合本来就是每会话一个状态机、一个聚合器选主形象；补的是显示：

| 主形象状态 | 单会话 | 多会话 |
|---|---|---|
| 工作中 | `Bash · 8/25` | `Bash · 8/25 · 3 会话` |
| 预警且只有它一个 | `连续 25 次读未写` | `连续 25 次读未写 · 共 3 会话` |
| 多个预警 | — | `连续 25 次读未写 · 另 1 个预警 · 共 3 会话` |

排序规则不变：预警优先，多个预警按最早进入预警的排；没有预警时按最近事件排。完整明细仍以 `GET /state` 的 `detail` 数组为准。

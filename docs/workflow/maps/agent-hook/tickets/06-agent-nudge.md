# 预警如何回到 agent 自己

## 问题

桌宠亮起之外，预警还要回到 agent：让模型知道「你已经连续读了很多次、没写任何东西」，并主动向用户报一句进展。

要定：

- 用哪个钩子事件注入（每条工具调用后最容易接上的那个），以及用哪个字段把话送进模型上下文——**等 01 给出确切字段名**。
- 话术：一句多长、说什么。要点是「报进展」而不是「停止工作」：例如「你已连续 22 次工具调用没有写入任何文件。向用户报一句当前在查什么、卡在哪。」
- 频率：每次越过阈值都注入会打断阅读节奏；是每次注入、还是每个会话只在第一次越线时注入。
- 会不会与桌宠的冷却冲突（两边各自独立计时，还是共用）。
- 若事实核查表明「注入模型上下文」不可用，退路是什么（给用户看的一条消息 + 桌宠，两路都只到人）。

类型：grilling
状态：已解决
阻塞于：01

## 已知事实

- **注入模型上下文可行**：`PostToolUse` 钩子返回的 `hookSpecificOutput.additionalContext` 会进入模型上下文；同一份输出里的 `systemMessage` 则显示给用户。两者可以同时给。
- `Stop` 钩子也能注入 `additionalContext`，但它是「回合结束」时触发，对本问题太晚。
- 注入不阻断：不需要 `decision: "block"`，不要用退出码 2（那会把 stderr 也塞给模型，语义变成报错）。
- **03 票已定**：话术由桌宠写在 `/event` 的 HTTP 响应体里，钩子脚本原样透传 stdout。所以本票只决定「桌宠什么时候、说什么」。桌宠不能撤回已经发出的事件——判定与亮图在同一时刻发生，话术随之。

## 答案

### 话术（注入模型上下文）

> 你已连续 **N** 次工具调用没有任何写入。先向用户报一句：你在查什么、已经查到哪、下一步打算怎么办。

硬一点：直白陈述加一个明确动作，不给「除非你判断还需要继续读」这类出口。措辞跑通后按体感再调。

### 给不给用户看

同一次响应里附一行极短的 `systemMessage`（如 `⏳ 连续 N 次读未写`），与桌宠气泡不重复。

### 频率

只在越过阈值的那一次注入；之后不再说话，直到出现写操作或用户发新消息重新计数。与 02 票的「冷却 = 解除条件」共用同一节奏，不另设计时。

### 模型不理它

第一版不加重、不升级、不阻断。`decision: "block"` 明确否决——它会强制模型结束回合，副作用太大。是否加重留到跑通后按体感再定（记在地图「尚未明确」）。

### 开关

注入、`systemMessage`、桌宠亮图三路各自在 `pet.config.json` 里有独立开关，可单独关闭；默认全开。

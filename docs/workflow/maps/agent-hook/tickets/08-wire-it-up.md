# 跑通最小闭环

## 问题

把前面各票的结论接起来，真跑一遍，拿「你被打断过一次，并且觉得这提醒有用」作为验收。

跑通要覆盖：

1. 桌宠常驻、置顶、可拖、点击穿透。
2. 在一个**不需要**改动任何文件的长阅读会话里，越过阈值后宠物亮起并弹气泡。
3. agent 收到预警并报了一句进展（若 06 判定此路不通，则只验两路到人）。
4. 一次真实的写操作后，预警自动解除。
5. 关掉宠物后，钩子不拖慢会话（对比开关前后的工具调用耗时）。
6. 事件日志里能读出那次预警的成因。

跑完把「哪里别扭」记进票，再决定是加票还是直接进润色。

类型：task
状态：已认领
阻塞于：02, 03, 05, 06, 07

### 待人工验收（票不能关）

1. 装钩子并重启 Claude Code 会话：`node agent-hook/hooks/install.js`；
2. 启动桌宠：`cd agent-hook/pet && npm start`；
3. 找一个**只读不写**的长任务让它跑，观察：桌宠是否亮、终端是否出现一行 `⏳`、模型是否主动报进展；
4. 若模型报进展或你自己已知道它在干嘛，觉得这提醒有用 → 票可关；若觉得阈值太松/太紧/话术不对，改 `pet.config.json` 再试。

### 已知取舍

- `toggles.pet` 关闭时主形象恒为空闲，但预警仍在后台计（并仍可能注入话术）——三个开关独立。
- 静音除了挡视觉，也会挡住后续的 alert 迁移（`state.js` 里 `!session.muted` 判断），所以静音期间不会收到话术。这是「我知道了我正忙」的语义。
- 时间窗判据在连续阈值很大时才有独立作用；两者叠加，任一先到即触发。

## 进展（2026-11-20，真实会话触发成功）

用户要求「一次一行地读、越过上限」来实测注入。在本会话里连续执行 25 次 `Read`（中间不写任何文件）：

- 第 25 次读触发：日志出现 `working → alert (consecutive-reads)`；
- **本会话的模型上下文中直接收到**注入话术：「你已连续 25 次工具调用没有任何写入。先向用户报一句：你在查什么、已经查到哪、下一步打算怎么办。」——这是 `hookSpecificOutput.additionalContext` 的实测证据，不是模拟器；
- 紧接着一次 `Edit`（修 bug）使状态回到 `working`，日志 `alert → working (write)`。

### 这轮暴露并修掉的两个 bug

1. **Bash 写正则误伤箭头函数**：`(^|[^>])>>?[^&]` 会把 `arr.map(x => x*2)` 里的 `=>` 当成输出重定向，导致只读命令被判成写、计数被清零。改成 `(^|[\s;&|(])[0-9]*>>?\s*[^&\s>=]`，并补了三条回归断言（箭头函数、`>=` 比较、`2>nul`）。
2. **退出时抛 ReferenceError**：`window-all-closed` 里还留着已删除的 `stopDragHelper()` 调用。已移除。

### 尚未由人确认的一项

票的验收标准仍是「你觉得这提醒有用」——注入本身已证明可用，但阈值是否合适、话术是否合适，需要你用自己的真实工作判断。

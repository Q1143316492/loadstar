调研与整理日期：2026-11-26

# 从移动端调用电脑上 Agent 工作环境：候选全景

> 所有事实来自本图 `research/` 下的六份调研，每份都标了来源性质与「未查到」。本文只做归类与取舍，不重复引用。
> 用户约束：中国大陆；手机端不能访问境外服务；不自配内网穿透；有阿里云服务器（包年低速带宽，约几百 K）；终端是 iPad + 安卓；不锁定 Claude Code；两个具体痛点是**局部看代码**与**输入斜杠命令**。

---

## 0. 先分清「谁在干活」和「手机看到什么」

这两个问题经常被混在一起，一混就会把「远程桌面」当成「移动 agent 客户端」。

**谁在干活**（执行位置）：

| 位置 | 含义 | 代价 |
|---|---|---|
| 家里 PC | 你现在的环境原封不动 | 必须开机、必须解决「手机怎么够到它」 |
| 你的阿里云服务器 | code 在云上，agent 在云上跑 | 代码要有一份云端工作副本；模型要能直连 |
| 厂商云 | WorkBuddy 云端沙箱 / TRAE 云端环境 | 代码要上厂商的机器 |

**手机看到什么**（界面层级，引自《移动端 Agent 客户端有哪些现成产品》）：

- **L1 终端镜像**：字符流。最省带宽，最不适合看 diff。
- **L2 会话视图**：对话 + 工具调用 + **diff 面板**。这是你要的「局部看改动」。
- **L3 任务面板**：看板 + 行内评论。

**顺序很重要**：先定「谁干活」，再选「用什么看」。反过来会选出一个接不上你代码的 App。

## 1. 八类候选

### A 类：整机远程桌面

手机/平板就是电脑的屏。

| 候选 | 门槛 | 国内链路 | 主要折扣 |
|---|---|---|---|
| **UU 远程** | 当前基础版免费、不限次不限时（官方 2026-11-19 公告，12-01 上线 VIP 后基础功能继续免费） | 厂商自建中转，**零配置、不需公网 IP** | 你在小屏上操作的是 Windows 桌面 |
| 向日葵 / ToDesk | 免费档 1080P/30 帧，付费 ￥158–468/年 | 同上 | 同上 |
| RustDesk | 自建中继要公网服务器 + 21115–21117 端口 | 官方只说「多数情况打洞成功」，无中国数据；安卓需侧载 APK | 不满足「不配穿透」 |
| AnyDesk | ￥145/月起 | — | 免费政策未查到 |

- **优点**：完全不改你的工作流；agent 还是你熟悉的那个；iPad 和安卓都有 App。
- **真正的痛点不是带宽，是输入映射**：触控板模式 vs 直接触摸、滚轮方向、修饰键。软键盘要专门调出来。
- **对你的两个痛点**：局部看代码 = 在一块被缩放的 1080p 画面里滚动，能看但很累；斜杠命令 = 照打不误，绕不过去。
- **带宽**：办公级 1080P 中继约 100 K/s 起。你的几百 K **够用，但不宽裕**。

### B 类：会话级接入（终端 / 网页 IDE）

| 候选 | 怎么连 | 是否要配穿透 |
|---|---|---|
| Termius / Blink Shell | 手机 SSH 到你电脑或服务器 | 需要一条到目标的路径（公网 IP、或 SSH 端口转发） |
| 阿里云 Workbench / 会话管理 | 浏览器直连 ECS | **官方明写「不必开通公网」**，但要一次安全组放行（47.96.60.0/24 等）+ 一次服务关联授权 |
| 腾讯 Cloud Studio | 浏览器开云端 IDE，官方兼容性页写明 Safari 15+ | 不需要，云 IDE 天生有公网入口；首赠 20 机时，1 核 2G 约 0.1 元/小时 |
| 华为 CodeArts IDE Online | 浏览器，官方明写有 WebTerminal | 同上 |

- **优点**：带宽极小（纯文本）；iPad Safari 能用。
- **硬伤（已核实）**：VS Code 系 Web IDE 在 iPad 上，**触屏选文本基本不可用**（microsoft/vscode #261958 仍 open：双击/长按选词失败，手指拖只滚动，只有手写笔能选）；code-server 官方 iPad 文档自己列了「键盘消失、无 Esc、终端复制粘贴问题」。
- **对两个痛点**：diff 只有纯文本 `git diff`；斜杠命令全靠手打。

### C 类：国产成品 App（手机是「遥控器」）

这是国内唯一已经把「手机接管电脑上的 agent」做成产品的类别。

| 候选 | 形态 | 链路 | 对你的两个痛点 |
|---|---|---|---|
| **WorkBuddy**（腾讯云） | 桌面端 + iOS/Android App；官方定位「手机成为桌面端 Agent 的远程控制台」 | **腾讯自己的加密中继，零配置、不需公网 IP** | 技能是「输入框 + → 使用技能」**点选**，不是打斜杠；产物卡片可看，但没有逐块 diff |
| **TRAE** | 移动端是「跨设备任务下发中心」，连桌面端 TraeWork；手机号登录，桌面端「设置 > TRAE 移动端 > 允许控制当前设备」，**连接有效期 180 天**，授权范围是电脑的 `/documents` 目录；Work / Code 两种模式各可选云端或电脑 | 厂商中继 | 技能是**点选**（选桌面端已启用的技能）✓；diff：**只有 App Store 文案说「支持 Unified Diff View」，官方文档未提、无截图**，按未证实处理 |
| **Kimi** | 手机控制桌面端 Kimi Work | 厂商中继 | 通用任务，非编码专用 |
| **CodeBuddy CLI** `/gateway` | 本地起服务，终端出二维码，手机开 Web UI（含 Web 终端） | 默认 Cloudflare Quick Tunnel（**国内稳定性无官方承诺**）；不装则退局域网 | 有终端，非逐块审阅 |
| **CodeBuddy CLI** 微信 channel | 微信里直接发消息驱动会话 | **纯国内链路** | 图文文件都通；界面是聊天 |
| **Qoder CN**（原通义灵码） | 移动端远程控制 + CLI 守护进程 + Cloud Agents | 厂商中继 | 未细查 |

- **为什么这一类有吸引力**：它们把「中继」这件事替你做了。你不想配穿透，而它们的中继是产品的一部分。
- **代价**：换掉你的 agent 和技能库。你的 `cwl-*` 技能、`docs/workflow/` 那套约定，搬不过去。

### D 类：开源移动客户端

| 候选 | 状态 |
|---|---|
| **Happy** | 唯一把「原生手机 App + 中继 + diff 取数」做齐的。默认中继国内可达（实测 0.21 s 建连），可 Docker 自建，App 内可改服务器地址。折扣：App 不在中区商店；diff 面板还在 roadmap；原 CLI 进维护模式，而桌面端不能配自建服务器 |
| Omnara | 已转型自有 agent 平台，旧移动 App 下架 |
| Vibe Kanban | 公司 2026-04-10 关停，云配对终止 |
| VibeTunnel | 仅 macOS/Linux，2026-08 起无提交 |
| Conductor | 站点 403，无可核实来源 |

- **对你的约束**：App 不在中国区商店这件事，对「不自配穿透」还能忍，但要多一步装 App。

### E 类：自建 —— DSH 架在阿里云

DeepSeek Harness（`dsh`），MIT 开源，你本机已有检出。

**能力面（正面对上你的痛点）**：

- 打 `/` 出**可点选的技能候选菜单**（`ui-skill` + `ui-input-trigger`），点选与手打 `/name` **走同一条 skill 注入路径**。
- 工具结果有专门的 `DiffBlock` 卡片（terminal / read / **diff** / search / web 五类）。
- 还有审批、agent 提问、计划、子代理、任务、轨迹、定时提醒。

**远程能力（版本关键）**：

| 版本 | 公网部署 |
|---|---|
| 你本机那份 `0.1.2-alpha.2` | `--host 0.0.0.0` **启动即报错**；服务器不带 TLS/认证 |
| npm 上的 `0.2.2-rc.5` | `--host <任意本机接口>`、`--public-url`、原生 `--tls-cert/--tls-key`，并附官方《Publish the Web UI behind a reverse proxy》 |

**没有官方中继、没有托管账号**（只有一个匿名 UUID）。跟 A/C 类正相反：中继得你自己解决，但 0.2 起「架公网」已是官方文档化场景。

**带宽实测**（把 `dsh-web-frontend` 解包、gzip -9 量）：

| 资源 | gzip |
|---|---|
| `vendor-*.js` | 175 KB |
| `index-*.js` | 146 KB |
| 全部 CSS | ~15 KB |
| **首屏合计** | **≈330 KB** |
| 全部 JS+CSS+HTML | 611 KB |

- 语法高亮按语言懒加载（cpp 44 KB / ruby 39 KB / html 27 KB，均 gzip 后）。
- `index.html` 带 viewport 与 `manifest.webmanifest`（`display: fullscreen`）→ **本来就是个 PWA，可加到主屏**。
- 会话流走 **WebSocket**，输出是文本 token。
- 你的带宽换算：330 KB 在 300 Kbps ≈ 9 秒、500 Kbps ≈ 5.3 秒、1 Mbps ≈ 2.6 秒。**首屏之后基本不占带宽。**

**代价**：代码得在服务器上（git 工作副本）；本机检出要升级；**没有任何移动端适配文档**，iPad/安卓真实体验未实测。

### G 类：借 IM 长连接驱动自己的 Agent

不改用厂商的 Agent，只用厂商的消息通道。

| 通道 | 接入方式 | 是否需要公网 IP | 备注 |
|---|---|---|---|
| **飞书** | 自建应用 + 官方**长连接**（`lark_oapi/ws`，WebSocket + 心跳） | **不需要** | **个人开发者可建应用，无需企业认证** |
| **钉钉** | 官方 **Stream** 模式 | **不需要** | |
| **微信个人号（ilink）** | 腾讯 `ilinkai.weixin.qq.com` HTTP 长轮询，扫码绑定 | **不需要** | **不用装新 App**；仅私聊、拉不进群；通道官方定性未核实 |
| **企业微信** | WebSocket 模式 | 不需要 | Webhook 模式需要公网 URL，别用 |
| **QQ 官方机器人** | WebSocket | 不需要 | 官方通道 |
| **QQ（NapCat / OneBot）** | WebSocket | 不需要 | 非官方，需小号 + 容器，有封号风险 |
| **WPS 协作** | WebSocket `wss://openapi.wps.cn/v7/event/ws` | 不需要 | 需 WPS 开放平台应用 |
| **微博** | WebSocket | 不需要 | 场景不对口 |
| Telegram / Slack / Discord / Matrix | 均主动外连 | 不需要 | **服务本身境内不可达**，排除 |
| LINE | Webhook | **需要** | 排除 |

国内可用的主动外连通道至少 8 个，详见 [im-channel-options.md](research/im-channel-options.md)。

现成实现：**cc-connect**（MIT，约 16.5k star）——支持 Claude Code、Qoder CLI、Kimi CLI 等，并可通过 **ACP 接入任意 agent**；飞书与钉钉均「无需公网 IP」；支持斜杠命令、流式回复、图片文件、语音 STT。

- **优点**：执行者是你自己的 Claude Code 或 DSH，厂商只搬消息；不需要公网 IP、不需要穿透、不需要服务器。
- **对两个痛点**：看 diff 只能让 agent 贴出来或自己跑 `git diff`（没有 diff 面板）；斜杠 skill 靠聊天里打 `/`。
- **安全**：桥接进程 = 能以你身份跑命令的聊天入口。白名单发送者、只开私聊、低权限运行、危险命令二次确认。消息内容会经过 IM 厂商服务器。

### H 类：自托管的移动端 Agent 网页界面

不再用厂商的界面，也不满足于聊天气泡——要的是**像终端里那个 agent 一样**的对话视图。

| 候选 | 特点 | 底座 |
|---|---|---|
| **`Ike-li/claude-chat-mobile`（CCM）** | Apache 2.0，Node ≥ 20。用 Agent SDK 驱动本机真实 `claude` CLI，同一份 CLAUDE.md / MCP / skills / 登录。审批卡、`AskUserQuestion` 点选、**`/` 斜杠命令含已装 skills**、工具卡预览变更、回合末文件变更汇总、`/rewind` 两步回退、锁屏推送、PWA 装到主屏 | **你的 Claude Code**（任何网关/国产模型都行） |
| `siteboon/claudecodeui`（CloudCLI） | 14.7k star，`npx` 即跑。内置终端、文件树（可编辑）、Git 暂存/提交/切分支 | Claude Code / Cursor CLI / Codex |
| DSH Web UI | `/` 技能菜单、`DiffBlock`、审批、子代理、轨迹 | DSH + DeepSeek |
| `devswha/ovis` | 浏览器与手机客户端，可经 SSH 连远程 PC，Web Push | 多 agent |
| `zhikunqingtao/zhikuncode` | 国产，Docker 一键部署，原生直连千问/DeepSeek | 多 agent |

**这一类没有自带国内可用的公网中继**，必须自己解决「手机怎么连」。详见 [selfhosted-mobile-webui.md](research/selfhosted-mobile-webui.md)。

### F 类：自建前端（把 DSH 当引擎）

DSH 的 ACP profile、TS/Python SDK、webhook 都是官方入口，不需要逆向。自建一个只为手机优化的界面，技术上完全可行，但要写代码和维护。

## 2. 三个必须先定的岔路

### 岔路一：代码在哪台机器上

这是整张图真正的分水岭，比选哪个 App 更上游。

| 代码位置 | 能选的类 | 你要做的事 |
|---|---|---|
| 家里 PC（Windows） | A、C（WorkBuddy/TRAE/Kimi 的「连接电脑」）、D（Happy） | 电脑常开；装对应客户端 |
| 阿里云服务器 | B、E、F | 代码 clone 一份到服务器；agent 在那边跑 |
| 厂商云 | C（WorkBuddy 云端 / TRAE 云端） | 代码上厂商机器 |

**判断**：你现在的工作目录在 Windows 上（`d:\Workspace\lodestar`）。如果走 E 类，意味着**「给 agent 干活的代码」和「你常年待的那份代码」不是同一份**，需要 git 同步往返。这不是不能做，但它是真实成本，得算进去。

### 岔路二：中继由谁出

| 谁出中继 | 候选 | 你的工作量 |
|---|---|---|
| 厂商 | UU/向日葵/ToDesk、WorkBuddy、TRAE、Kimi、Qoder | 零 |
| 厂商（可选自建） | CodeBuddy `/gateway`（Cloudflare） | 装个 cloudflared |
| 开源中继，可自建 | Happy | 装 App（不在中区商店） |
| **IM 厂商，只搬消息** | 飞书长连接 / 钉钉 Stream + cc-connect 或自写桥接（G 类） | 建个自建应用 + 装桥接 |
| **没人，你自己** | DSH、Cline、OpenHands、自建前端 | 反代 + TLS，或 SSH 转发 |

### 岔路三：换不换 agent

- 保 Claude Code 工作流 → A（整机）、E/F（自建）、**G（IM 桥接）**、**H（自托管移动界面）**
- 能换 → C 类立刻可用，且自带 diff 视图

## 3. 四条推荐路线

### 路线甲：先用成品验证「这件事值不值得做」

**WorkBuddy** 或 **TRAE**，二选一。

- WorkBuddy：技能是点选的（正对你的输入痛点），中继是腾讯的，iOS/安卓都有。
- TRAE：能连已配对的个人电脑，技能同样是点选；**官方商品页声称有 Unified Diff View，但文档未展开，别把它当成已验证的能力**。

**为什么先做这个**：它们是**唯一能今天装上、今晚就用**的形态，不需要你动服务器、不需要升级 DSH、不需要反代。用它来回答一个更重要的问题——**「在外出时真的会打开它吗」**。如果答案是不会，后面所有的自建都不必做。

**代价**：你的 `cwl-*` 技能和 `docs/workflow/` 约定用不上。

### 路线乙：保住自己的工作流，把 DSH 架到阿里云

1. 服务器上把 `@deepseek-ai/dsh` 升到 0.2.x
2. 代码 clone 一份到服务器
3. `dsh --profile web --public-url https://你的域名/ --tls-cert ... --tls-key ... --trusted-host 你的域名`
4. 手机浏览器打开，**加到主屏**（PWA，第二次进基本瞬开）
5. 技能用 `/` 菜单点选，改动看 `DiffBlock`

**为什么这条可能最合你意**：它同时解掉两个痛点（`/` 菜单 + diff 卡片），而且 agent 是你自己那套。带宽实测够用。

**代价与风险**：
- 代码要有一份在服务器上（git 往返）
- 要自己架 TLS（原生或反代）
- **没有移动端适配文档，iPad 上到底什么样，谁都没验证过**
- 单用户设计：带 token 的 URL 就是钥匙；建议用低权限用户跑 agent

### 路线丙：不换 Agent，只换通道 —— IM 桥接

代码留在原地，agent 还是 Claude Code，只是把「手机 → 电脑」这段换成飞书/钉钉的长连接。

1. 飞书建一个**企业自建应用**，开事件订阅（长连接模式），订阅 `im.message.receive_v1`
2. 电脑上跑桥接（**cc-connect** 现成，或自己接 `lark_oapi.ws.Client`）
3. 桥接把消息交给 `claude -p`（无头模式，可 `--resume` 续会话）或 DSH 的 ACP profile
4. 输出流式回发到飞书

**为什么这条值得认真考虑**：
- **不需要公网 IP、不需要穿透、不需要服务器**——你的电脑主动外连
- **执行者是你自己的 agent**，厂商只搬消息，不进你的代码
- 代码不用搬到云端，`d:\Workspace\lodestar` 原地不动
- iOS 和安卓都能用（飞书 App 两端都有）
- 顺带解决「任务完成没」的通知问题——聊天本身就带推送

**代价与风险**：
- **没有 diff 面板**。看改动只能让 agent 贴出来，或自己跑 `git diff`——这是它相对路线乙最大的短板
- 消息内容（含贴出的代码片段）会经过飞书服务器
- 桥接进程 = 能以你身份跑命令的聊天入口，安全配置不能省（白名单、只开私聊、低权限、危险命令确认）
- cc-connect 接 DSH（ACP）**协议对得上但没有实测**

### 路线丁：保住 Agent 体验 —— 自托管移动网页界面

**如果「像在 Agent 里对话」这件事本身就是需求**（而不只是「能下指令」），IM 桥接不够，要上 H 类。

首选 **`Ike-li/claude-chat-mobile`（CCM）**：

- 它驱动的就是**你电脑上那个 `claude`**——同一份 CLAUDE.md、MCP、skills、登录、权限规则，不是另一个 agent。
- 手机端把终端里的事补齐了：审批卡（含「中止本轮」对齐 `Esc`）、`AskUserQuestion` 点选、`/` 斜杠命令列候选并带 skills 说明、`@` 引用文件、工具卡预览变更、回合末文件变更汇总、`/rewind` 两步回退、锁屏推送、PWA。
- 它的 README 写明是给「官方 Remote Control 进不去的人」做的，典型场景就是**在 `claude` CLI 里接了中转、第三方模型、国产模型**——正好是你的处境。

**剩下的唯一难点是「手机怎么连」**，因为这一类都不带国内外可用的中继：

| 做法 | 算不算「配穿透」 | 代价 |
|---|---|---|
| **跑在阿里云上** | **不算**，服务器本来就公网可达 | 代码和 `claude` 都在服务器上，Windows 那份不是同一个 |

## 4. 关于「自己做一个中控」

**先别做。** 理由：

1. DSH 0.2 的 Web UI 已经是一个能架公网的 agent 控制台，能力面覆盖你要的「展示和控制」。
2. 自建前端的前提是你已经知道现有界面的**具体哪里不行**。现在没人知道——没有移动端适配文档，也没有实测。
3. 一旦知道哪里不行，改造点会很具体（比如「`DiffBlock` 在 390px 下横向溢出」），那时再写几十行 CSS 或一个薄前端，比现在从头设计便宜得多。

**该做的顺序**：先跑通 E 类，拿 iPad 真实用一次，把卡点记下来；卡点如果集中在样式，改 DSH 的前端插件；如果集中在交互模型，再考虑 ACP 自建。

## 5. 安全（架公网前必读）

- **认证是单用户凭据**：`--trusted-host` 只是信任围栏，真正鉴权的是 URL 里的 launch token + 签名 cookie。**那个 URL 就是钥匙。**
- 必须全程 HTTPS。`http://` 的浏览器侧会在明文里暴露 launch token。
- 反代要保留 `Host`、剥挂载前缀、转发 `Upgrade`、改写 cookie 的 `Path`/`Secure`、`/ui` 302 到 `/ui/`——官方指南逐条写了。
- 监听端口本身不受信任围栏保护，要限制到可信代理或内网。
- agent 用低权限用户跑，别用 root。

## 2. 开源方案

### 2.1 RustDesk

**架构（官方文档）**：两个可执行文件——`hbbs` 是 ID/会合（信令）服务器，`hbbr` 是中继服务器。连接流程：客户端持续向 `hbbs` 上报自己的地址端口 → 主控向 `hbbs` 请求与被控通信 → **`hbbs` 先尝试打洞直连；打洞失败才走 `hbbr` 中继**。官方原话：「在大多数情况下打洞成功，中继服务器根本不会被用到。」**没有给出成功率数字**。
来源：[Self-host 文档（官方仓库原文）](https://github.com/rustdesk/doc.rustdesk.com/blob/master/content/self-host/_index.en.md)，官网同文 `https://rustdesk.com/docs/en/self-host/`。

**自建要什么**：

- **一台有公网 IP（或公网域名）的服务器**。若把服务端放在家里 NAT 后面，会遇到 NAT 回环（hairpin）问题，必须开路由器的 NAT loopback 或用内网 DNS 绕开——官方专门有一篇排障文。
  来源：[NAT Loopback issues](https://github.com/rustdesk/doc.rustdesk.com/blob/master/content/self-host/nat-loopback-issues/_index.en.md)。
- **端口**：最小需 TCP `21115`–`21117` + UDP `21116`；Web 客户端另需 TCP `21118`/`21119`。也支持只开 TCP 443 的 WSS 模式，但该模式下**只能走中继，没有 P2P 直连**。
- **配置要求极低**：「最低配的基础云服务器就够，CPU 和内存需求都很小」，树莓派亦可。
- **带宽**：中继一条连接的流量「1920×1080 屏在 30 K/s 到 3 M/s 之间，取决于分辨率与画面刷新；只做办公用途约 100 K/s」。
  来源：[安装文档](https://github.com/rustdesk/doc.rustdesk.com/blob/master/content/self-host/rustdesk-server-oss/install/_index.en.md)。

**不自建**：官方提供**免费公共服务器**（FAQ 中出现「Our free public server」），社区版自建**无需许可证、免费**。
来源：[官方 FAQ wiki](https://github.com/rustdesk/rustdesk/wiki/FAQ)。

**手机端现状**：**Android 已从 Google Play 下架**（官方说明是为防诈骗，官方讨论 #5660），Android 需从官网/GitHub 侧载 APK；**iOS 仍在 App Store**（官方 FAQ 给出 App Store 链接）。
来源：同上 FAQ wiki。

**中国大陆打洞成功率**：**未查到**任何官方或可引用的大样本数据。第三方文章只笼统说「NAT 条件一般时 P2P 有时打不通，会转中继」。
来源：[腾讯云社区，2026-11-23](https://cloud.tencent.com/developer/article/2791393)（第三方博客，利益相关）。

### 2.2 Sunshine + Moonlight

定位是**自建游戏串流**（Sunshine 是被控端，Moonlight 是客户端），不是远控 SaaS，**没有任何中继基础设施**。

**外网访问方式（官方 Setup Guide）**：
1. 在路由器上开 **UPnP** 自动端口映射（Sunshine 内置该选项）；或
2. 装 **Moonlight Internet Hosting Tool** 维持端口映射；或
3. 用 **ZeroTier / Tailscale / NordVPN Meshnet** 组虚拟局域网。
官方明确列出失败场景：**「被运营商级 NAT（CGNAT）挡住、家里有双路由器」** 时自动方案不工作。外网串流要求主机上行 ≥ 5 Mbps。iOS/tvOS 客户端**必须先在局域网内完成配对**。
来源：[Moonlight Setup Guide（官方 wiki）](https://github.com/moonlight-stream/moonlight-docs/wiki/Setup-Guide)。

**在中国的实际可用性**：未查到针对中国大陆的官方说明或可引用评测；从上面的机制看，它把「有没有公网入口」的问题原样转嫁给用户（要么端口映射，要么自建 VPN）。

### 2.3 Deskreen

Deskreen CE 是 Electron 应用，用 **WebRTC 把电脑屏幕实时推到任意带浏览器的设备**上——定位是「把任意设备变成第二块屏 / 屏幕共享」，**不是远程输入控制工具**；README 明确社区版功能受限，完整功能留给 Pro。
来源：[Deskreen 仓库 README](https://github.com/pavlobu/deskreen)。

**结论（事实层面）**：它能让你在手机浏览器里**看**到桌面，但没有提到能把触控转成被控端输入，因此不构成「用手机驱动 agent」的链路。

## 4. 不需要穿透的替代路径

### 4.1 把 agent 跑在云主机上，手机只连云端

这条路把「家里的 NAT」整个绕开：家用 PC 不再是服务端，云端那台机器天生有公网 IP，手机用 SSH 或浏览器终端接入。成本即 §3.3 的 ￥45/月起。

可用的接入层：

- **Windows 自带 OpenSSH Server**（按需功能，Server 2025 起默认安装），手机装任意 SSH 客户端即可。
  来源：[Microsoft Learn：OpenSSH for Windows 入门](https://learn.microsoft.com/zh-cn/windows-server/administration/openssh/openssh_install_firstuse)。
- **Web 终端**：`ttyd` 把命令行暴露成网页，手机浏览器直接开。
  来源：[tsl0922/ttyd](https://github.com/tsl0922/ttyd)。

### 4.2 Windows 自带远程桌面（RDP）

- 手机端有官方客户端：Windows App / 远程桌面客户端覆盖手机、浏览器等。
  来源：[Microsoft Learn：远程桌面客户端](https://learn.microsoft.com/zh-cn/windows-server/remote/remote-desktop-services/clients/remote-desktop-clients)。
- **限制**：只有 Windows 专业版/企业版/教育版/Server 能当 RDP **主机**，**家庭版不能**（只能当客户端）。
  来源：[Microsoft Learn：在电脑上启用远程桌面](https://learn.microsoft.com/zh-cn/windows-server/remote/remote-desktop-services/remotepc/remote-desktop-allow-access)。
- 外网访问仍需端口映射或 VPN——官方文档本身建议只在可信网络（如家庭网络）启用。

## 5. 两类链路各自的现实限制（只写有来源的）

### 5.1 手机控制整个桌面

- **输入映射是主要难点**：手机只有手指，屏幕又小，「精准模式」做得好不好决定能不能点中 3 像素的目标。三家的做法不同：ToDesk 提供「触控板模式 / 直接触摸模式」；向日葵的「鼠标增强」先显示十字线再确认，精度高但多一步。
- **滚轮方向与修饰键映射**：用 iPad/Mac 控 Windows 时，滚轮方向与 Ctrl/Cmd/Win 映射容易错乱，各家在设置里提供「跟随系统/兼容模式」或修饰键映射。
- **移动端多一层工具栏**：UU 远程在手机端进桌面后要旋转屏幕，并通过侧边工具栏的 [操作]、[键盘] 等按钮完成配置——即软键盘/按键是额外的、需要手动调出的层。
- 来源：[个人评测《手机远程控制电脑实测》，2026-11-26](https://www.hqwc.cn/a/1760812.html)（**来源性质：个人站点、当日发布、内容农场式行文，只能当轶事，不能当决策依据**）；[UU 官方帮助](https://uuyc.163.com/help/20241203/40220_1197649.html)（一手）。

- **弱网差异有实测**：ZOL 在 1 Mbps 限速下测，向日葵仍可控制、ToDesk 卡顿后断连；ToDesk 官网宣传的 1–3 ms 延迟在家庭网络下「几乎无法复现」。
  来源：[ZOL 横评，2026-09-08](https://m.zol.com.cn/article/12451765.html)（媒体评测，**结论一边倒向向日葵，疑似赞助稿**，数字请打折看）。

- **软键盘遮挡输出**：**未查到**任何可引用的评测正面讨论这一点。只能从「需要专门调出键盘工具栏」间接看出输入是被特殊处理过的——这属于推断，不是评测结论。

### 5.2 手机只接入命令行会话

- 结构上简单：Windows 开 OpenSSH Server（内置，无需第三方），手机 SSH 客户端连；或用 ttyd 开个网页终端。
- 带宽与画质问题消失（纯文本），但**窄屏 + 软键盘**的排版问题依旧存在，且**未查到**可引用的实测来量化。
- 若 agent 跑在云端，则连「家里有没有公网 IP」都不再是变量（§4.1）。

## 对下游决策最关键的事实

1. **UU 远程目前仍是「基础远控免费、不限次不限时」**，VIP 定档 2026-12-01 上线，官方承诺基础功能不涨价（2026-11-19 公告）。「免费版封顶 1080P/30」只是第三方说法，官网没有。
2. 其余三家的免费档都写死在 **1080P / 30 帧**：向日葵、ToDesk 官网明示；AnyDesk 价格页从 ￥145/月起，免费政策查不到。
3. **家用宽带没有公网 IP 这件事，商业远控不受影响**——它们靠厂商自己的服务器中转，用户侧零配置；这正是它们与 RustDesk/Moonlight 的分水岭。
4. **RustDesk 自建必须有公网服务器**（端口 21115–21117 + UDP 21116）；服务端极轻，但打洞失败转中继时按 30 K/s–3 M/s 烧流量，办公级约 100 K/s。
5. RustDesk 官方只说「多数情况打洞成功」，**没有任何中国成功率数据**；Android 已从 Google Play 下架，需侧载 APK。
6. **Tailscale 在中国大陆没有 DERP 节点**（最近香港/东京/新加坡）；中国区 App Store 已下架 iOS 版（用户报告）；2026-08 还有中国移动线路丢 TLS ClientHello 导致控制面连不上的案例，官方明确不为 DPI 妥协。
7. **ZeroTier/Tailscale 的国内体验证据只有作者评测级**（少数派 2026-05）：握手慢、成功率无保障、DERP 限速严重。
8. 自建控制面（Headscale）需要公网服务器 + 80/443 + UDP 3478；frp 同样需要公网服务器。**这条路绕不开「租一台有公网 IP 的机器」。**
9. 腾讯云轻量当前最低 2 核 2G / 3 Mbps / 200 GB，**￥45/月**；另有 200 Mbps 峰值 + 无限流量的锐驰型同为 ￥45/月。
10. **最省事的绕开方式**：agent 跑云主机，手机 SSH / 浏览器终端接入——不依赖家里 NAT，成本与第 9 条相同。
11. RDP 只在 Windows 专业版及以上能做主机，家庭版不行；Windows 自带 OpenSSH Server 可直接开。
12. 手机控整个桌面的真正痛点是**输入映射**（触控板/直接触摸、滚轮方向、修饰键），不是带宽；这一点有三方评测与官方帮助佐证。
13. 「剪贴板」「软键盘遮挡」这两项**没有任何可引用的一手数据**，判断时别当作已知。

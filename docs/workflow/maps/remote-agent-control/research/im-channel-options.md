# 「主动外连」的聊天通道清单：不只是飞书和钉钉

> 起因：用户问「只有飞书和钉钉可以吗」。
> 方法：读 `chenhg5/cc-connect` 的 `README.zh-CN.md` 支持状态表与各平台接入文档（`docs/feishu.md`、`docs/weixin.md`、`docs/qq.md`、`docs/wps-xiezuo.md`）。未实测。

---

## 1. 完整清单

判据仍是**连接方式**：只要你的机器主动外连，就不需要公网 IP、不需要穿透。

| 平台 | 连接方式 | 需要公网 IP | 国内可直接用 | 备注 |
|---|---|---|---|---|
| **飞书** | WebSocket（官方 SDK `lark_oapi/ws`） | 否 | 是 | **个人开发者可建应用，无需企业认证** |
| **钉钉** | Stream（官方 SDK） | 否 | 是 | |
| **企业微信** | WebSocket / Webhook | WS 否 / Webhook 是 | 是 | 用 WebSocket 模式即可 |
| **微信个人号（ilink）** | HTTP 长轮询，网关 `ilinkai.weixin.qq.com` | 否 | 是 | **不用装新 App**；仅私聊；机器人不能被拉进群 |
| **QQ（NapCat / OneBot）** | WebSocket | 否 | 是 | 非官方桥接，要额外 QQ 小号 + NapCat 容器，有封号风险 |
| **QQ 官方机器人** | WebSocket | 否 | 是 | 官方通道 |
| **WPS 协作** | WebSocket `wss://openapi.wps.cn/v7/event/ws` | 否 | 是 | 需 WPS 开放平台应用 |
| **微博** | WebSocket | 否 | 是 | 场景不太对口 |
| Telegram | Long Polling | 否 | **需代理**（境内被封） | 对本人不可用 |
| Slack / Discord / Matrix | Socket Mode / Gateway / long polling | 否 | 否（服务本身不可达） | 不在候选 |
| LINE | Webhook | **是** | 否 | 唯一要求公网 URL 的，排除 |

结论：**国内可用的主动外连通道至少 8 个**，飞书与钉钉只是我核实过官方 SDK 源码的两个代表性选择。

## 2. 对你最有意义的三个

### 2.1 飞书：个人也能建应用

`docs/feishu.md` 原文：

> **个人用户也可以创建**：飞书开放平台支持个人开发者创建应用，无需企业认证。

这条很关键——不需要公司账号，自己注册就能开。而且 cc-connect 有 `cc-connect feishu setup` 一条命令扫码新建，会「自动预配权限与事件订阅」并回填 `app_id`/`app_secret`。

文档同时写明：

> **优势**：使用长连接模式，无需公网 IP、无需域名、无需反向代理（ngrok/frp）

### 2.2 微信个人号（ilink）：最省事的入口

- 走腾讯 `ilinkai.weixin.qq.com` 网关，`getUpdates` 长轮询 + `sendMessage` 下发。
- `cc-connect weixin setup --project my-project` 一条命令出二维码，微信扫码登录，自动把 token / account_id 写回配置。
- **不用装任何新 App**——手机上的微信本来就是最常开的。
- 能力：文字、引用、语音转写文本；图片/文件/视频可下载（AES-128-ECB 解密）+ 可下发；无转写文字时可走 STT（依赖 ffmpeg）。
- **限制**：个人微信 ilink 机器人不是普通微信好友，**拉不进群**，只能私聊。
- **安全**：`allow_from` 必须填，空或 `*` 表示不限制发送者（官方文档自己标「不安全，仅建议本机调试」）。扫码后会自动回填扫码者 ID，但仍建议核对。

**未核实**：ilink 通道的官方定性（是否为腾讯对外正式开放的机器人能力、使用条款是否允许此类自动化）。`weixin.qq.com` 域名表明是腾讯自有网关，但本次没有查到对应的官方开放平台文档。用之前建议自行确认，避免账号风险。

### 2.3 企业微信：注意模式

- WebSocket 模式不需要公网；**Webhook 模式需要公网 URL**。
- cc-connect 的能力表注释原文：「企业微信：Webhook 模式需要公网 URL；长连接等模式多数不需要。」

## 3. 该怎么挑

| 你的情况 | 选 |
|---|---|
| 想要最稳、能力最全、能开群 | **飞书**（个人可建应用，五步配完） |
| 想少装一个 App、手机上最顺手 | **微信个人号（ilink）** |
| 公司本来就用企微 | **企业微信 WebSocket 模式** |
| 想用官方 QQ 通道 | **QQ 官方机器人** |
| 有 WPS 365 | **WPS 协作** |
| 谁都不想注册 | **自写**：飞书/钉钉官方 SDK 各几十行也能跑起来 |

**唯一硬性失败**：任何要求公网 URL 的模式（LINE、企微 Webhook）——那等于让你做穿透。

## 4. 对下游决策最关键的事实

1. 国内可用的主动外连通道至少 8 个，选择面远不止飞书与钉钉。
2. **飞书个人开发者无需企业认证即可建应用**，这是最容易上手的一条。
3. **微信个人号（ilink）不用装新 App**，走腾讯自家网关、长轮询，但要接受「仅私聊 + 官方定性未核实」。
4. 企业微信要选 **WebSocket 模式**，Webhook 模式会把你拖回公网。
5. Telegram / Slack / Discord 服务本身在境内不可达，不进入候选。
6. `allow_from` 这类发送者白名单是默认不安全的（空 = 任何人），必须显式配置。

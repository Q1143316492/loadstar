# 候选方案全景与推荐组合

## 问题

把六份调研并成一份全景：按**形态**分类（整机远程桌面 / 会话级接入 / 托管云端环境 / agent 专用移动客户端 / 国产成品 App / 把 agent 搬到服务器上自建前端），每一类下列出具体候选、各自的门槛（月费、被控端要求、是否要配置穿透、是否依赖境外服务）、以及在 iPad 与安卓上的真实表现。

然后给出**推荐组合**：主选一条、退路一条，并说明各自在「局部看改动」和「输入斜杠命令」两个痛点上的具体做法。

判断标准（用户口径）：国内可直连、不自配穿透、iPad 与安卓都能开、能顺手看 diff 和发指令。不强求唯一解，允许多方案并存。

类型：grilling

## 答案

2026-11-26 整理成 [全景文档](../panorama.md)。因为用户明确要求「铺全景而不是用问题收窄」，本文档取代了逐条盘问。

要点：

- **六类候选**：A 整机远控（UU/向日葵/ToDesk）、B 会话级接入（Termius / 云 IDE）、C 国产成品 App（WorkBuddy / TRAE / Kimi / CodeBuddy / Qoder）、D 开源移动客户端（Happy）、E DSH 架阿里云、F 自建前端。
- **三个上游岔路**：代码在哪台机器、中继由谁出、换不换 agent。这三件事比选哪个 App 更决定成败。
- **推荐两条路线**：
  - **甲（先验证）**：WorkBuddy 或 TRAE。零配置、厂商中继、iOS/安卓俱全、今天就能装。TRAE 官方写明手机端有 Unified Diff View，WorkBuddy 的技能是点选而非打斜杠——恰好各自命中一个痛点。代价是换掉自己的技能库。
  - **乙（保工作流）**：DSH 0.2 架到阿里云，原生 TLS + `--public-url`，手机加到主屏当 PWA。`/` 技能菜单 + `DiffBlock` 同时解两个痛点，首屏约 330 KB gzip，几百 K 带宽够用。代价是代码要有云端副本、要自己架 TLS、且**移动端体验无人验证过**。
- **关于自建中控：先别做。** 现有界面已经够，但没人知道它在 iPad 上具体哪里不行；先跑通再按真实卡点改，比现在从头设计便宜。
- 安全：单用户凭据，带 token 的 URL 就是钥匙；必须全程 HTTPS；agent 用低权限用户跑。

未决、留给下一票：真机上到底能不能用，以及「甲/乙」怎么选 → 已毕业为 [最终走哪条路线](11-route-choice.md)。

# 跑通一条最小闭环

## 问题

按 [全景](../panorama.md) 的两条路线，真实走一遍：iPad（或安卓平板）上发一条指令 → agent 干活 → 在平板上局部浏览改动 → 回到会话继续。记录卡在哪、哪些环节体验不达标、需要换哪一块。

**这条票的答案只能来自真机**——六份调研里没有任何一份能回答「DSH 的 Web UI 在 iPad 上到底什么样」，官方也没有任何移动端适配文档。

分两段做，甲段随时可做、乙段需要服务器事实：

**甲段（零成本，先做）**：装 WorkBuddy 或 TRAE 的手机 App，连上家里的 Windows PC，在平板上走一遍「下指令 → 看改动」。目的不是选它，是回答一个更上游的问题：**外出时你真的会打开它吗**。若答案是不会，乙段与自建都不必做。

**乙段（需要先知道服务器情况）**：阿里云那台的公网可达性、系统、内存、能否开端口、带宽档位（固定带宽还是峰值+流量包）。确认后在服务器上升级 `@deepseek-ai/dsh` 到 0.2.x、clone 一份仓库、用原生 TLS 起 `dsh --profile web`，手机加到主屏，量首屏耗时与交互手感。

记录要具体到可执行：哪个操作卡了、卡在渲染还是网络、软键盘有没有遮挡、`DiffBlock` 在窄屏是否溢出。

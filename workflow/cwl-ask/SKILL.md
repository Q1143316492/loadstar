# 问路

你不记得每个技能，所以问。说清楚两件事：**手上是什么**（一个想法、一个 bug、一段读不顺的文档……）和**要的产出是什么**。

我指路，你输入：本库多数技能是**用户调用**（只有你手打名字才会启动），少数**模型可触发**（我可以直接带上）。本页只是路标——要引用某个技能的具体做法、或建议跳过某一步之前，我会先读那个技能的 `SKILL.md`。

## 速查

| 你的处境 | 用它 |
|---|---|
| 有个想法，还没想透 | `cwl-grill-with-docs` |
| 聊透了，要变成可执行计划 | `cwl-to-plan` |
| 手上有计划 / ticket，要写代码 | `cwl-implement` |
| 代码写完了，要挑毛病 | `cwl-code-review` |
| 干完一段，想改进环境 | `cwl-retro` |
| 想法太大，一个会话装不下 | `cwl-wayfinder` |
| 东西坏了，且难缠 | `cwl-diagnosing-bugs` |
| 要查资料（文档 / API 事实） | `cwl-research` |
| 库越改越难受，想巡检 | `cwl-improve-codebase-architecture` |
| 设计问题在纸上说不清 | `cwl-prototype` |
| 换会话 / 换人，要交接 | `cwl-handoff` |
| 「别说了，画给我看」 | `cwl-show-me` |
| 文档列举了却不展开、读不顺 | `cwl-doc-quality` |
| 一次性的小事 | 什么都不用，直接说 |

速查给答案，下面几节给例外和口径。

## 主流程：想法 → 落地

盘问 → 计划这两步要在**一个不中断的上下文窗口**里完成，之后的实现各开新窗：

1. **`cwl-grill-with-docs`** —— 盘问澄清；边盘边把术语写进 `GLOSSARY.md`、把决策落成 ADR。想法还糊从这里开始。
2. **`cwl-to-plan`** —— 把对话综合成 spec + 一组曳光弹 ticket（写进 `docs/specs/<slug>/`，ticket 带「阻塞于」字段）。它**不做访谈**——只综合已聊过的；要再盘，回上一步。
3. **`cwl-implement`** —— 按 ticket 或 spec 实现，在约定接缝上调 `cwl-tdd`。**不自动提交**：做完给你改动概要和一份建议的提交信息，提交由你决定。
4. **`cwl-code-review`** —— 两轴评审（标准 / Spec），只读只报告。`cwl-implement` 收尾会带上它；想单独评审一段 diff 也可以直接用。
5. **`cwl-retro`** —— 在**刚干完的同一个会话里**复盘：提的是环境改进（导航、检查、规范），不是代码意见。

## 匝道：先产生工作，再并入主流程

- **想法太大、装不进一个会话**（新项目、大特性） → **`cwl-wayfinder`**：把路画成 `docs/maps/<努力名>/` 下的**决策 ticket** 地图，一次解一张，产出决策、不施工。地图清了就**交接**：你把出口并入 `cwl-to-plan`，把一串决策收拢成可执行的计划。它慢且重，只为真装不下的想法准备——范围明确的特性留在 `cwl-grill-with-docs`。
- **东西坏了、且难缠**（第一眼看不出的、时好时坏的、两个已知良好状态之间的回归） → **`cwl-diagnosing-bugs`**：它拒绝在建出**能打红的紧回路**之前谈原因，修完带回归测试。修好后在**同一会话**手打 `cwl-retro`，问「什么本可以防住它」；如果发现的是「没有可锁定的接缝」，那是 `cwl-improve-codebase-architecture` 的活。
- **要查资料** → **`cwl-research`**：后台智能体查一手来源（官方文档、源码），留一张带引用的 Markdown 笔记。拿到后回主流程——它喂思考，不替思考。

## 保养：不是功能开发

- **`cwl-improve-codebase-architecture`** —— 平时有空就跑：扫描**加深机会**，以 HTML 报告呈现（写系统临时目录，不进仓）。选中一个候选，就等于**生出一个想法**，带进主流程继续。

## 旁路与随用

- **`cwl-prototype`** —— 一个设计问题（状态模型对不对、UI 该长什么样）纸上说不清时，用一次性原型给出能跑 / 能看的答案。要离开当前会话去做原型、再带结果回来，用 `cwl-handoff` 当进出门。
- **`cwl-handoff`** —— 只在**要携带**时用：换 harness、换目录、交给别人、阶段中途分叉。同一个 harness、同一个目录，就不用它（见「会话边界」）。
- **`cwl-show-me`** —— 解释不清时换个呈现：图、调用树、代码形状草图。
- **`cwl-doc-quality`** —— 审一篇「列举了却不展开」的文档；报告、README、设计文档都行。

## 底层：被引用，不用刻意记

五个砖，由上面的技能按需带上（也能直接点名）：**`cwl-grilling`**（盘问原语）、**`cwl-domain-modeling`**（`GLOSSARY.md` 与 ADR）、**`cwl-codebase-design`**（深模块词汇：模块 / 接口 / 深度 / 接缝 / 适配器 / 杠杆 / 局部性）、**`cwl-tdd`**（红 → 绿循环的参照）、**`cwl-writing-for-agents`**（给 agent 写文档的参考）。

## 会话边界：换不换窗口，怎么换

一个**阶段**是会话里的一段工作（盘问、实现、评审）。在阶段与阶段的**边界**上，你有五个选项，按这个顺序想：

1. **继续** —— 原地不动，零成本零损失。**先排除它**再谈换：保持对话作为一手来源是默认，换窗口丢掉的都是真的丢了。
2. **开新窗口** —— 这里的一切对下一步都不重要时，才清掉重来。
3. **`cwl-handoff`** —— 要**携带**才用：换 harness、换目录、交给同事、或一个阶段中途要分叉出去。
4. **子智能体** —— 任务足够独立、能无人值守跑完时，扔进一个独立窗口，拿回一份报告。
5. **压缩** —— 没有更便宜、更精确的选择时的**默认退路**，不是第一选择；压缩会把细节抹平，之后留下的是一份自信但失真的摘要。

**在边界上做决定。**阶段中途只有两个选项：继续，或把剩余拆成子智能体。

## 也可能：什么都不用

一次性的小改动、一个直接的问题——**直接说就行**。技能是给有形状的工作的：想法要盘、计划要拆、bug 要回路、库要巡检。没那个形状，省下这一步。

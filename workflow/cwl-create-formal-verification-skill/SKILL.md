**先读 `docs/workflow/AGENTS.md`**（若存在）：本项目自己的工作流约定。

测试检查的是**有人想到要写的那些情况**。形式化验证检查**一个声明过的范围里的每一种情况**：一个模型里所有步骤顺序、有界范围内的所有输入、或者所有输入。

这个技能找到仓库里最要紧的那一处，验一条性质，留下一个**项目本地技能**，让下一个 agent 拿它检查改动。写那个技能时，假定读者是一个**中途接手、从没见过你的工作、当场冷读**的 agent。

用户要能信任结果、并据此行动，**不需要学那门验证语言**。

## 从代码里选目标

从代码里回答，只有从代码里看不出来的才问用户。用户点名了某个区域或某个 bug，就从那里开始。

一个好的目标，是**代码做出的一项承诺**，它一旦被打破会伤到用户，**而测试很少能触及打破它的那种情况**。选仓库里**最强**的那个目标，不是最好验的那个。

## 让问题来选工具

挑成本最低、能回答问题的那个工具：模型检查器、证明助手、SMT 验证器，或别的。

| 问题 | 工具 |
|---|---|
| 事件能不能以坏顺序发生 | 模型检查器，模型建在设计的一小块上。**TLA+ 是这件事在任何语言里的默认** |
| 代码本身对任意输入是否安全（内存安全、溢出、数据结构不变量） | 跑在**代码**上的验证器 |
| 这门语言没有能跑的验证器 | 直说，然后用**生成的输入**测真实代码，不用手搓一个模型 |
| 要求在所有规模上都成立、有界不够 | 定理证明 |

优先选**这个仓库的开发者能装上、能跑**的工具，并告诉用户你为什么选它。

## 什么算好

- **忠于代码。** 模型或证明的每一部分都指向一个评审者能打开的文件。验证当成一个不可分割的步，在代码里也必须是一个不可分割的步。名字用这个仓库的。
- **能失败。** 从没见过它失败的检查什么也证明不了。每条性质都要在**故意改坏的代码变体**上失败一次——删掉一个检查、调换一个步骤。
- **发现就是发现。** 当前代码破坏了性质时，用代码的词报告反例。把性质或模型放宽到通过为止，等于把发现吃掉；改产品代码要用户点头。
- **对范围诚实。** 说清验的是什么、在什么边界和假设下、什么没验。一次通过覆盖的是模型或边界，不是整个系统。
- **不学工具也能读。** 性质和它带来的伤害，各用一句人话。反例用代码的词讲成一段短步骤序列。
- **重跑便宜。** 一条命令、一个可复现的工具版本、短到下一个 agent 愿意在每次相关改动上跑。
- **跟代码同步。** 记录每项检查覆盖哪些文件和函数，以及**上一次确认验证仍描述当前代码的那个 commit**。被覆盖的代码在这之后变了，下一个 agent 就该知道这份验证需要再看一眼。

## 生成那个验证技能

产物的落点是 `docs/workflow/formal/<名字>/`：一个 `SKILL.md`，加上它要跑的规格或脚本。这个目录和 `docs/workflow/verify/<名字>/`（`cwl-create-verification-skill` 产出的驱动手册）分开——两者都叫「验证」，但管的事不同：`verify` 验程序现在能不能用，`formal` 验设计在所有顺序下会不会坏。

写一个项目本地技能，frontmatter 里点名它管的区域和什么时候用它。没有 frontmatter 的技能不会注册。

**光看那个技能，下一个 agent 就要能判断四件事**：

1. 这次改动有没有碰到被验的代码
2. 怎么跑检查
3. 失败时，这是真的 bug 还是建模错误
4. 如果是有意的改动，怎么更新验证

把**覆盖记录**和**同步 commit** 写进技能，并告诉下一个 agent：只有确认验证仍描述新 commit 上的代码之后，才把这个 commit 往前移。

用这个仓库真实的命令、路径和名词，不留占位符。

**如果检查是 TLA+ 模型**，告诉下一个 agent 用 `/statechart` 读每一次结果——它把每条违反的不变量画成最短路径，用平白的句子讲出来；通过时它画出系统在状态间怎么移动。**按名字引用它**，它的命令、选项和文件路径会随版本和机器变化，一个都不要抄进生成的技能或脚本里。

本地没有 `statechart` 时，直接用 TLC 读结果；要画图时见 `docs/learn-pstack/statechart.md`。

## 交接前先证明它

照着生成出来的技能走一遍，**像下一个 agent 那样**：在一个临时改动上把真实代码改坏，让它破坏那条性质。它必须抓住。

然后撤掉临时改动，确认检查回到原状：通过，或者只在你准备报告的发现上失败。

**从没跑过的验证技能是草稿。** 它漏掉了那次破坏、或者某一步跑不起来，修技能或修验证，而不去修那个临时改动。

## 交接

告诉用户：

- 验了什么、用了哪个工具、为什么用它
- 边界与假设
- 检查在平白的话里发现了什么
- 怎么跑
- 什么没覆盖

找到了一个接近的第二个目标时，才建议它。要在一段时间之后把验证拉回同步，指向 [`cwl-maintain-formal-verification-skill`](../cwl-maintain-formal-verification-skill/SKILL.md)。

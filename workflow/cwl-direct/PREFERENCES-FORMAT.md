# 项目偏好格式

偏好放在**项目里**，由 `cwl-direct` 读取：

- 首选 `docs/workflow/PREFERENCES.md`；
- 没有 `docs/workflow/` 的项目，用项目根的 `PREFERENCES.md`。

项目里的这份文件归项目自己维护；`cwl-sync` 只覆盖技能目录，不会碰到它。

## 模板

自由写即可，建议分三节：

```markdown
# 项目偏好

## 验证 / 编译节奏

- 所有改动做完后统一编译一次。
- 只有改的是编译配置、或正在排查编译错误时，才在中途编译。

## 范围

- 测试只跑与改动相关的目标。
- 改动停留在任务指定的文件范围内。

## 收尾

- 最后跑一次 `<项目命令>`，贴出输出；有失败就报失败数与关键错误。
```

## 写法要求

- 写成对 agent 的直接指令，描述要做成什么样，避免「别做 X」这类否定句。
- 只写这个项目特殊的规则；通用规则别重复。
- 一条一行；冲突时，越靠前越优先。
- 重工具链的项目（游戏引擎、大型构建），值得明确写清「什么时候编译 / 启动编辑器 / 跑构建」。

---
name: cwl-implement
description: "根据一份 spec 或一组 ticket 实现一项工作。"
disable-model-invocation: true
---

实现用户在 spec 或 ticket 里描述的工作。

如果用户传入了一个 ticket 引用（文件路径或编号），先读回它，并在开始前报出它的标题。引用有歧义就问。

在预先约定的接缝处，尽可能调用 Skill 工具运行 "cwl-tdd"。

经常跑类型检查，经常跑单个测试文件，最后完整跑一遍测试套件。

**报完成之前先过证据门。** 没在本次消息里跑过、看过输出的结论，不许说成「通过 / 修好 / 完成」；跑完整命令、数清失败数、贴关键输出，「应该」「大概」「看起来」一律视为没验证。能用一条命令证明的，就用那条命令证明。

完成后，调用 Skill 工具运行 "cwl-code-review" 评审这份工作。

**处理评审意见时**（报告、或用户转达的反馈）：逐条对照代码核实，再决定技术性接受或带理由反驳；不要表演性同意（「你说得对！」这类客套只是噪音），也不要照单全收——评审者可能缺上下文。

不要提交：把改动概要和一份建议的提交信息报告给用户，由用户自己提交。

# 学习记录格式

学习记录放在 `./learning-records/`，按顺序编号：`0001-slug.md`、`0002-slug.md`……目录惰性创建：写第一条记录时才建。

它们是教学版的 ADR：记录不那么显然的结论、关键洞见，以及用户自述的既有知识——这些会指挥以后的会话。它们用来推算最近发展区。

## 模板

```md
# {学到了什么、或确立了什么的短标题}

{1–3 句：学到了什么（或确立了哪些既有知识），以及它为什么影响以后的会话。}
```

格式就这些。一条学习记录可以只有一段话。价值在于记下*这件事现在算知道了*、以及*它为什么改变接下来该教什么*，而不在于把各个小节填满。

## 可选小节

只在真正有价值时才写。多数记录用不到。

- **状态**：早先的理解被推翻、被替代时有用，写 `状态：superseded by LR-NNNN`。
- **证据**：用户是怎么证明理解的（答对的问题、完成的练习、提到的既有经验）。这条论断日后可能被翻案时有用。
- **影响**：它为以后的会话解锁了什么、排除了什么。不明显时值得记。

## 编号

扫 `./learning-records/` 里现有的最大编号，加一。

## 什么时候写

下面任一条成立就写：

1. **用户证明自己真懂了一件不平凡的事**：不是「接触过」，而是有证据说明他能正确使用这个概念。这为接下来该教什么定了新的下限。
2. **用户透露了既有知识**：「这个我已经会了。」记下来，免得以后的会话重复教。也记下他说到的深度。
3. **纠正了一处误解**：用户原先信错的东西，现在明白了为什么错。这类价值很高：它们预示相关主题上以后的绊脚石。
4. **使命因学习而转向**：用户发现自己在意的其实是另一回事。链到 [[MISSION.md]] 并更新它。

### 什么不算

- 只是「讲过了」的材料。讲了不等于学会，等证据。
- 已经以术语定义的形式简短记在 [[GLOSSARY.md]] 里的东西。不要重复。
- 逐次会话的活动日志。学习记录不是流水账：它们是决策级的洞见。

## 替代

后来的记录与早先的冲突（用户的理解加深或纠正了），把旧记录标成 `状态：superseded by LR-NNNN`，而不是删掉。理解如何演变的历史本身就是有用的信号。

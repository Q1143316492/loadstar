# MISSION.md 格式

`MISSION.md` 放在工作区根目录，记录用户学这个主题的*原因*。每一个教学决定（接下来教什么、把哪些资源摆到台面、设计哪种练习）都应当能追溯到这份文档。

## 模板

```md
# 使命：{主题}

## 为什么
{1–3 句。用户追的那个真实世界里的具体目标。学会之后，他的生活或工作会有什么变化？避免「理解 X」这类抽象说法，往背后的结果上推。}

## 算成功的标志
- {用户能做到的具体、可观察的一件事}
- {另一件具体的事}
- {……}

## 约束
- {时间、预算、既有承诺、学习偏好——任何限制做法的东西}

## 不在范围内
- {用户明确表示此刻不追的邻近主题，用来守护最近发展区}
```

## 规则

- **一个工作区一个使命。** 想学两件不相关的事，就是两个工作区。
- **具体胜过抽象。** 「十月前跑完半马」胜过「身体练好点」；「给我团队交付一个 Rust CLI」胜过「学 Rust」。
- **含糊就回推。** 用户说不出为什么，就先访谈，别动笔。糟糕的使命比没有使命更糟。
- **现实变了就修订。** 使命会变。用户目标挪了，就更新这份文件：不要留一份过期的使命去指挥以后的会话。
- **保持短。** `MISSION.md` 超过一屏，它就不再是罗盘，而变成计划了。

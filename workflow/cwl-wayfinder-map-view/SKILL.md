**先读 `docs/workflow/AGENTS.md`**（若存在）：本项目自己的工作流约定。

一张地图摊在 Markdown 里，读者得自己从十张票里拼出「哪条是主干、现在该做哪张」。这一页替人拼好：票按依赖深度分波排开，顶上一条「现在」点名下一张，其余票压成卡片，点开才看要点。

分工是死的。**壳**由 `TEMPLATE.html` 提供，逐字节复用，你不改它。**判读**由你写：读完整张地图，决定每张票叫什么、在哪一波、要定什么。你的产出是一份 JSON，`render.js` 拿它对账、灌进壳、落到临时目录。

```text
读地图  →  写判读 JSON  →  render.js 对账并渲染  →  打开
```

## 1. 读整张地图

读 `map.md` 的三节（目的地、备注、已定决策），再读 `tickets/` 下每一张票的三行元信息（`类型：` `状态：` `阻塞于：`）、`## 问题`，以及已解决票的 `## 答案`。

未结的票**不在** `map.md` 里——「已定决策」只列已解决的，票的清单只在 `tickets/` 目录。状态与阻塞关系一律从票文件读，不从印象里写。

**完成判据**：每张票的元信息都在手上，不看原文也能说清它要定什么。

## 2. 写判读

写一份 JSON 到系统临时目录。形状见下「判读契约」。三处是质感的关键：

- **短名**是名词短语，读者靠它在版面上认出这张票。
- **gist** 一句话回答「这张要决定什么」，不是复述背景。
- **brief** 讲结构与节奏：哪条是主干、哪条在跑、哪几张可以插空。它是一段判断，票只是它的依据。

**完成判据**：每张未关闭的票都有一条；`now` 点名的那张确实可开工或已认领；`points` 是压过的判断，不是 `## 问题` 的原文。

## 3. 渲染

```bash
node <技能目录>/render.js <判读.json> docs/workflow/maps/<地图名>
```

**完成判据**：退出码 0，最后一行是产出的绝对路径。`ERR` 逐条改掉再跑；`WARN` 逐条看一眼——「票没有进判读」多半是漏了一张。

## 4. 交出去

打开那个文件，把绝对路径给用户，一句话说这页怎么读。地图变了重跑同一条命令即可，覆盖同一路径。

## 判读契约

```json
{
  "name": "多 agent 监控平台地图",
  "slug": "agent-monitor",
  "updated": "2026-11-22",
  "brief": "两步主干：先把「仓库与目录边界」和「server 的位置与状态归属」定死，动手迁移才动得了；事件 schema 这条已经查完，接下来接统一 schema。",
  "now": { "id": "01", "why": "两张主干里编号最靠前的一张。定完它，动手迁移才少一个变量。" },
  "waveNotes": ["五张并行的起点；其中 03 已定。", "等第一波里对应的那张定完。", "压轴，得等 schema 定死。"],
  "tickets": [
    {
      "id": "01",
      "short": "目录怎么搬",
      "gist": "wo-agent 怎么进 lodestar，原仓库之后留不留。",
      "type": "grilling",
      "status": "待办",
      "blockedBy": [],
      "file": "tickets/01-repo-layout.md",
      "points": ["submodule / subtree / 搬家 / 复制，四选一", "原仓库冻结，还是继续双向同步", "hooks 算 client 还是独立一类"]
    }
  ]
}
```

- `type` / `status` / `blockedBy` / `file` 照抄票里的四行；`render.js` 会和票文件逐条对账。
- `points` 3–4 条。未解决的票写「要定的」——每条一个决定；已解决的票写「结论」——每条一个已定事实（从 `## 答案` 里压）。
- `waveNotes` 一波一行，按顺序；多出来的波次没有笔记就留空字符串。
- 已关闭的票不进判读：它们属于「超出范围」，不在路线上。

**版面宽度**（`render.js` 会量，超了报 `ERR`）：`short` ≤ 6.5、`gist` ≤ 24、每条 `points` ≤ 23、`brief` ≤ 100、`now.why` ≤ 45。全角算 1、半角算 0.5。

## 页面读法

- **波次** = 依赖深度。第一波是没有未解决前置的票，下一波等上一波定完；同一个数上并列的票互不相干，可以并行。
- **「现在」** 是 `now.id` 那张，配一句为什么是它、同批还有哪些、谁在做。它可开工时标题写「现在」，已认领时写「进行中」。
- **卡片** 默认显示类型、短名、gist、以及被谁挡着；点开给出 `points`、前置与解锁、票的路径。
- **连线** 从源卡底边出发、落到被解锁那张的顶边，箭头指向被挡的那张。鼠标停在任意卡片上，它整条上下游链变实、其余淡出。

这页只回答「现在做什么、下一步是什么」。雾、超出范围、票的正文都留在 `map.md` 与票里，想看原文顺着卡片上的路径去开。

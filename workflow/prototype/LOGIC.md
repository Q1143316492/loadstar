# 逻辑原型

一个单文件、自包含的 HTML（一个**可分享 demo**），让任何人点着按钮就能驱动一个状态模型。问题关于**业务逻辑、状态迁移或数据形状**时用它：这类东西在纸面上看着都合理，只有推过真实情形才感觉不对。

因为是零安装的单文件，你可以直接把它丢给非开发者（设计、PM、领域专家），让他们自己上手感受模型。所以它说的是他们的语言，不是代码的语言。

## 什么时候是正确形状

- 「我不确定这个状态机能不能处理先 X 后 Y 的情况。」
- 「这个数据模型真的能表达……这种情况吗？」
- 「我想在写之前先感受一下 API 该长什么样。」
- 任何「有人想**按按钮、看状态变化**」的场合。

问题若是「这个该长什么样」，那是错误分支。用 [UI.md](UI.md)。

## 流程

### 1. 写下问题

写代码之前，先写下你要原型的状态模型和要回答的问题。一段话，放在 demo 顶部（可见的介绍里，不只是注释）。答错问题的逻辑原型是纯浪费，所以把问题写明确，之后（不管用户是当场盯着还是回头再看）都能核对。

### 2. 把逻辑隔离成可携带的模块

把真正的逻辑（回答问题的部分）写进单个 `<script>` 块，做成一个小而纯的模块，将来可以原样抬走、放进真实代码库。周围那页用完即弃；这个模块不是。

正确的形状取决于问题：

- **纯 reducer**：`(state, action) => state`。动作是离散事件、状态是单个值时好用。
- **状态机**：显式的状态与迁移。「此刻哪些动作本来就是合法的」也是问题的一部分时好用。
- **一小组纯函数**作用于一个普通数据类型。没有隐含的当前状态、只有变换时好用。
- **一个有清晰方法面的类或模块**，当逻辑确实拥有持续的内部状态时。

选最贴合问题的形状，*而不是*最容易接上页面的形状。保持纯净：不碰 DOM、不碰 `document`、按钮处理器不伸手进去。页面单向调用它，反向没有任何东西流回。这正是让原型超出自身寿命还有用的原因：问题一旦回答完，验证过的 reducer / 状态机 / 函数组会自己抬进真实模块。

### 3. 构建可分享的 HTML 文件

一个文件，纯 HTML/CSS/JS：不用框架、不用打包器、不用服务器，全部内联，双击即开，经得起转发给别人。任何人打开就能跑。

写给非开发者看。每个标签都用**领域语言**，不是代码：按钮和状态读起来像业务，不像 reducer。用大白话解释正在发生什么。

布局要有干净的层次，从上到下：

1. **标题和一行说明**，讲清这个 demo 让你探索什么（第 1 步的那个问题）。
2. **当前状态**：完整的相关状态，渲染成可读的面板（带标签的字段，不是裸 JSON dump），每次点击后重新渲染，让变化可见。有助于非开发者跟上的地方，点名「刚刚变了什么」。
3. **自由操作按钮**：每个动作一个按钮，始终可用，任何人都能任意顺序拨弄模型。每次点击派发它的动作并重渲染状态。
4. **引导式走查**：一组**场景**，每个标签页一个。每页是一段平实语言写的场景说明（它搭出的局面、要看什么），下面依序是该场景的**按钮**。每一步都是真按钮：点击就执行该动作并前进到下一步。开始一个走查会重置到已知的初始状态，让场景每次都跑得一样。

选那些演示尴尬情形的场景——纸面上难以推理的：正常路径、刁钻的边界、一次「本来就不该合法」的尝试。

保持好看但克制：干净的排版、大方的留白、一个主色。不要动画、不要花活：没有任何东西与状态和按钮争注意力。

### 4. 交出去

把文件发给他们，或替他们打开。他们有空就会点走查和自由操作；有意思的时刻是他们说「等等，这不应该可能」或者「咦，我以为 X 会不一样」——那些是*想法*里的 bug，这正是全部意义所在。他们想要新动作或新场景就加上。原型会演化。

### 5. 收敛答案与原型

原型回答了它的问题后，先收敛答案，再按 [SKILL](SKILL.md) 里的方式收敛原型。逻辑专属的映射：验证过的 reducer / 状态机 / 函数组抬进真实模块（决策被吸收）；HTML 外壳随它去那个把原型作为一手来源留着的一次性分支——因为它是单文件，在那里随时仍能重跑。

## 反模式

- **不要加测试。** 需要测试的原型就不是原型了。
- **不要接真实数据库。** 用内存状态，除非问题专门关于持久化。
- **不要泛化。** 不写「以后如果要支持 X 呢」。原型只回答一个问题。
- **不要把逻辑和页面揉在一起。** 纯模块一旦引用 DOM、`document` 或按钮处理器，就不再可抬走。页面保持为覆在纯模块上的薄壳。
- **不要上框架、打包器或服务器。** 收件人双击就能开的单文件；一个 React 应用或 dev server 就毁了「可分享」。
- **不要把 HTML 外壳带进生产。** 页面是为手工点按优化的。它背后那个逻辑模块才是值得留下的部分。

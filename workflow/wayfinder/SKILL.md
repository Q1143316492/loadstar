一个松散的想法来了：太大，一个 agent 会话装不下，还裹在雾里——从这里到**目的地**的路还看不见。探路是找到那条路，而不是一头冲向目的地。本技能把路线画成仓库里的一份**共享地图**（`docs/maps/<努力名>/`），然后一次解决一张它的**决策 ticket**（一张 ticket 是一个「答案是决策」的问题，不是一牙要执行的构建切片），直到路清晰。

目的地因事而异，给它命名是画图的第一件事：它塑造每一张 ticket。它可能是一份要交接出去迭代的 spec、一个要在规划开始前锁定的决策，或者一个就地执行的变更（比如一次数据结构迁移）。地图与领域无关：工程工作、课程内容，只要形状合适都行。

## 只规划，不动手

wayfinder 默认是**规划**：每张 ticket 解决一个决策，路清晰时地图就完成了——在有人真正去干那件事之前，没有任何东西还需要决定。想直接动手的冲动，通常正是你摸到地图边缘、该交接了的信号。一项努力可以在自己的**备注**里覆盖这一点，把执行也纳入地图；但没有这句话时，产出的应该是决策，不是交付物。

## 按名字引用

每张地图和 ticket 都有**名字**：它的标题。在人看的任何东西里（叙述、地图的「已定决策」），都用这个名字称呼它，绝不用裸编号。一排 `01、02、03` 是看不清的；名字一眼就能读。编号和路径不会消失：名字里包着链接，但它们骑在名字*里面*，绝不代替名字。

## 地图

地图是单个文件 `docs/maps/<努力名>/map.md`，是本次努力的权威产物。它的 ticket 是 `docs/maps/<努力名>/tickets/` 下的文件。

地图是**索引**，不是仓库：它列出已做出的决策，并指向持有细节的 ticket；一个决策只住在一个地方——它自己的 ticket——所以地图从不重述它，只给一行摘要加链接。

### 地图正文

整个地图的低分辨率视图，每个会话加载一次。未结的 ticket **不**列在这里：它们是 `tickets/` 里状态仍为「待办」或「已认领」的票据，靠扫描找到。

### Ticket

每张 ticket 是 `tickets/` 下的一个文件（`NN-<slug>.md`），从 `01` 起按依赖顺序编号（阻塞者在前）。它的正文是那个问题，大小以装得进一个 agent 会话为准：

```markdown
## 问题

<这张 ticket 要解决的决策或调查>

类型：research | prototype | grilling | task
状态：待办 | 已认领 | 已解决 | 已关闭
阻塞于：NN, NN（没有就写「无」）
```

每张 ticket 的 `类型：` 取值 `research`、`prototype`、`grilling`、`task` 之一（见下文「Ticket 类型」）。`类型` 是 ticket 携带的唯一标记，绝不带实现类的状态标记：它们是决策，不是实现工作。

一个会话**认领**一张 ticket 的方式是动手之前**先把** `状态` 改成 `已认领`，让并行的会话跳过它。这个标记*就是*认领：`状态：待办` 的 ticket 就是敞开的。

阻塞由 `阻塞于：` 行表达。一张 ticket 在它列出的每一张都「已解决」时**解除阻塞**；**前沿**就是状态为「待办」、无阻塞、未认领的那些，也就是已知的边缘。

答案不写在正文里；它在解决时被记录（见「推进地图」）。解决过程中产生的产物从票里链接（相对路径），不要粘贴进来。

## Ticket 类型

每张 ticket 要么是 **HITL**（人在环，和一个代表自己的人一起做），要么是 **AFK**（agent 单独驱动）。HITL 的 ticket 只能通过那场当场交流解决；agent 绝不替人扮演交流的另一边（一个自问自答的盘问 agent 已经破坏了这一点）。

- **Research**（AFK）：读文档、第三方 API，或本地资源（知识库），以浮现一个决策所等待的事实。由调用 `research` 技能的子智能体解决。需要当前工作目录之外的知识时用。
- **Prototype**（HITL）：做一个便宜、粗糙、具体的东西给人反应（提纲、草稿、桩，或 UI / 逻辑代码），以此提高讨论的保真度——调用 `prototype` 技能。关键问题是「这该长什么样」或「这该怎么表现」时用。原型作为产物链接进票里。
- **Grilling**（HITL）：对话。默认情形。总是调用 Skill 工具两次，传入 `grilling` 和 `domain-modeling`。
- **Task**（HITL 或 AFK）：在能做*决策*之前必须先做的手工活：没有可决策、可原型、可研究的东西，但讨论被它卡住。注册某个服务以便评判其 API、开通访问权限、把数据挪个位置以便看清它的形状。这是唯一「做」而不是「决策」的类型，它靠为决策解除阻塞而立足，不靠交付目的地。agent 能单独干就单独干（AFK）；否则给人一份精确的清单（HITL）。活干完即解决；答案记录做了什么、以及后续 ticket 依赖的事实（凭据在哪、新 URL、行数）。

## 战争迷雾

地图是*刻意*不完整的：画不了的就别画。在活着的 ticket 之外是**战争迷雾**：你察觉得到要来、却还钉不准的决策与调查的暗淡视野，因为它们挂在还没解决的问题上。解决一张 ticket 就清开它前面的雾，把现在能说清的东西逐个毕业成新的 ticket，直到通往目的地的路清晰、不再有票剩下。

地图的**尚未明确**一节就写这种暗淡视野：怀疑中的问题、以后要回访的区域。它是*朝着*目的地的未发现前沿：这里的一切都在范围内，只是还没锋利到能开票。写得或松或详，随视野而定；它同时也是给协作者的路标，让人看到这次努力朝哪去。

**雾还是票？** 测试是「你现在能不能把问题说精确」，*不是*「你现在能不能回答它」。

- **能开票**：问题已经锋利，哪怕它被阻塞、你还动不了它。
- **放进「尚未明确」**：你还说不那么锋利的问题。不要把迷雾预先切成票大小的块：它比票更粗，一块雾可能在触及前沿时毕业成几张票，也可能一张都不是。

**尚未明确**不含已经决定的（「已定决策」）、已经是活票的、以及超出范围的（下一节）。

## 超出范围

雾只会*朝着*目的地聚。目的地划定范围，所以它之外的工作是**超出范围**：不是雾，也不属于「尚未明确」。它在地图上有自己的**超出范围**一节：被你有意识判定在*本次*努力之外的工作。决定它归属的是范围，不是锋利度。

超出范围的工作永不毕业（前沿止于目的地），所以它只有在目的地被重划时才会回来，而且那时是一次全新的努力，不是续跑。

把某件事判出范围是一个划范围的动作，不是路线上的步骤。当一张已存在的票被发现坐在目的地之外（画图时误圈进来，或被某次解决暴露出来）时，**把它标记出局**——把 `状态` 改成「已关闭」（明确离开前沿）——并在**超出范围**一节留一行：要点加为什么出范围，链接那张票。它不进**已定决策**——那里记录的是实际走过的路线；范围边界不是路线上的步骤。

## 调用

两种模式。无论哪种，**一个会话绝不解一张以上的票**，`research` 票例外。

### 画地图

用户带着一个松散的想法调用。

1. **命名目的地。** 调用 Skill 工具两次，传入 `grilling` 和 `domain-modeling`，钉死这趟地图要探向什么：spec、决策或变更。目的地划定范围，所以先定它。
2. **探一遍前沿。** 再盘一轮，这次**广度优先**：横扫整个空间而不是钻任何一条线，浮现出悬念中的决策与眼下能走的第一步。**如果这一轮没探出雾**（通往目的地的路已经清楚，整段旅程小到一个会话装得下），你不需要地图。停下，问用户想怎么继续。
3. **创建地图**：`docs/maps/<努力名>/map.md`，填好目的地与备注，已定决策留空，雾勾进**尚未明确**。
4. **写出你现在能说清的票**，从 `01` 起按依赖序编号（阻塞者在前），各自填好「类型」「状态：待办」「阻塞于」。写不清的一律留在雾里：**尚未明确**一节。
5. **放研究子智能体。** 对你刚创建的每张 `research` 票，起一个调用 `research` 技能的子智能体并行解决；发现写到 `docs/maps/<努力名>/research/<名字>.md`，从票里留一条上下文指针指过去。
6. 停：画图是一个会话的活；它一张票也不亲手解决。

### 推进地图

用户带着一张地图（路径或努力名）调用。ticket 是**可选**的：不带票时，由你（而不是用户）挑下一个决策。

1. 加载**地图**：低分辨率视图，不是每张票的正文。
2. 选票。用户点名了就用它。否则按顺序取前沿第一张。**认领它**：动手之前先把 `状态` 改成 `已认领`。
3. 按它 `类型` 行点名的方式解决（见「Ticket 类型」）。先读类型行，再看正文：正文不写类型。**按需缩放**：随时取任何相关或已解决的票的全文；调用 `## 备注` 点名的技能。拿不准就调用 Skill 工具两次，传入 `grilling` 和 `domain-modeling`。
4. 记录解决：把答案写进票文件（追加 `## 答案` 一节），把 `状态` 改成 `已解决`，然后往地图的「已定决策」追加一条**上下文指针**。
5. 加入新浮现的票（续编号、填「阻塞于」）；把答案使其能说清的雾毕业成票，并从**尚未明确**里清掉对应的雾（它此后只住在它的新票里）。如果答案揭示某张票（本张或其他）坐在目的地之外，**判它出范围**，而不是让它留在路线上解决。如果这个决策让地图的其他部分失效，更新或删除那些票。

用户可以并行跑无阻塞的票，所以随时可能有别的会话在改同一批文件。
